Практика на паре - слайды 30-32 лекции 1 (Scanner, System.out, Java Code Conventions)

Что здесь решается

На слайдах 30-32 презентации первой лекции - девять маленьких задач с общей схемой: прочитать числа через Scanner, что-то посчитать, вывести через System.out. Слайд 30: три суммы (первые N целых чисел, ряд дробей, знакочередующийся ряд). Слайд 31: геометрия (круг, прямоугольный треугольник, расстояние между точками). Слайд 32: три преобразования треугольника (сдвиг, масштабирование, поворот). У слайдов своя нумерация: на слайде 32 задачи снова идут как 1, 2, 3, поэтому ниже они названы "слайд 32, задача 1" и так далее.

Каждая задача - отдельная программа в своём .java файле. Общие требования со слайдов: осмысленные имена переменных, ввод через Scanner, результат через System.out.println(), N типа int, дробные числа типа double, вывод с 2-4 знаками после точки, код по конвенциям Java, проверка на разных значениях.

Что реально проверено. Все девять программ скомпилированы (javac из JDK 25, ключ -Xlint:all - ни одного предупреждения; компиляция с --release 8 тоже проходит, то есть в коде нет ничего новее Java 8) и запущены на примерах со слайдов и на своих значениях - всего 46 запусков. Каждый результат пересчитан независимо на Python другим способом (для суммы 1..N - формула Гаусса вместо цикла, для рядов - math.fsum, для расстояния - math.dist, для поворота - умножение комплексных чисел на e^(i·угол)) - все 46 совпали. Вывод в блоках ниже настоящий: программы запускались в псевдотерминале, поэтому набранное число видно рядом с приглашением, как в обычном терминале.

Общие правила, по которым написаны все программы (тема слайда 30 - Java Code Conventions)

- Имя файла = имя public-класса. Класс пишется с большой буквы, слова слитно (SumOfIntegers, CircleCalculator). Все девять имён разные, чтобы программы спокойно лежали в одном проекте.
- Переменные и методы - с маленькой буквы, слова слитно (sum, legA, angleRadians). Имя говорит, что лежит внутри: radius, hypotenuse, perimeter. Однобуквенные имена только там, где они общепринятые или прямо взяты из условия: n (сколько членов ряда), k (номер члена), i (счётчик цикла), x и y (координаты), dx и dy (вектор сдвига).
- Отступ 4 пробела, открывающая скобка на той же строке, что и if/for/метод, один оператор на строку.
- Ввод - только Scanner. Приглашение печатается через System.out.print (без перевода строки, чтобы число набиралось рядом с приглашением), результат - через System.out.println().
- N - int, дробные числа - double. Единственное исключение: сумма 1+2+...+N в задаче 1 - long (почему, объясняется в самой задаче).
- Дробный результат печатается через String.format. "%.4f" - четыре знака после точки (суммы рядов), "%.2f" - два (геометрия). Расшифровка шаблона: % - начало, .4 - сколько цифр после точки, f - число с фиксированной точкой; округляет Java сама.
- В начале main там, где есть дробные числа, стоит Locale.setDefault(Locale.US). Locale - набор региональных настроек, в том числе какой знак отделяет дробную часть. Зачем это нужно - см. "Частые ошибки" внизу; коротко: на компьютерах с русской или казахской локалью без этой строки Scanner не принимает "2.5", а вывод получается с запятой. Обратная сторона: дробные числа теперь нужно вводить через точку, как на слайдах.
- В исходниках только ASCII: английские приглашения и комментарии, чтобы не зависеть от кодировки файла на чужом компьютере.
- scanner.close() - сразу после последнего чтения (как в lectures/01).

Слайд 30 - суммы

Общая идея всех трёх задач - копилка (в программировании такую переменную называют накопителем, accumulator). Сначала копилка пуста: sum = 0. Потом N раз подряд считаем очередной член ряда и кладём его в копилку: sum += член (это то же самое, что sum = sum + член). В конце печатаем содержимое копилки. Это и есть схема со слайда: ввод N, повторить N раз "посчитать следующий член и добавить к S", вывод S. Задачи отличаются только тем, ЧТО именно кладётся в копилку на каждом шаге.

Задача 1. Сумма первых N целых чисел

Сначала руками, N = 5. Копилка 0. Кладём 1 - в копилке 1. Кладём 2 - стало 3. Кладём 3 - 6. Кладём 4 - 10. Кладём 5 - 15. Ответ 15, как на слайде. Цикл for делает ровно это: k пробегает значения 1, 2, ..., N, и на каждом шаге sum += k.

Файл SumOfIntegers.java

```java
import java.util.Scanner;

public class SumOfIntegers {
    public static void main(String[] args) {
        Scanner scanner = new Scanner(System.in);

        System.out.print("Enter N: ");
        int n = scanner.nextInt();
        scanner.close();

        if (n < 1) {
            System.out.println("N must be a positive integer.");
            return;
        }

        long sum = 0;
        for (int k = 1; k <= n; k++) {
            sum += k;
        }

        System.out.println("Sum = " + sum);
    }
}
```

Запуск, пример со слайда (N = 5):

```
Enter N: 5
Sum = 15
```

Другие значения (настоящие запуски, вывод сокращён до ответа): N = 1 - Sum = 1; N = 10 - Sum = 55; N = 100 - Sum = 5050; N = 100000 - Sum = 5000050000; N = 0 и N = -3 - сообщение N must be a positive integer.

Почему сумма типа long, а не int. int хранит целые примерно до 2,1 миллиарда (точнее, до 2147483647). Сумма 1+2+...+100000 равна 5000050000 - больше. Java при переполнении int не выдаёт никакой ошибки: число молча "заворачивается", как одометр в машине, который после 999999 снова показывает 000000. Реально: та же программа с int sum вместо long sum на N = 100000 печатает Sum = 705082704 - неверно и без единого предупреждения, а на N = 5 даёт те же 15, что и правильная. Поэтому слайд и просит проверять разные N: на примере со слайда такой баг не виден.

Проверка вторым способом - формула Гаусса. Числа 1..N можно складывать парами с двух концов: 1+N, 2+(N-1), 3+(N-2) и так далее. Каждая пара даёт N+1, пар получается N/2, значит сумма равна N·(N+1)/2. Для N = 5: 5·6/2 = 15. Для N = 100000: 100000·100001/2 = 5000050000 - именно так независимо проверен вывод программы.

Проверка N. По слайду N - положительное целое. Если ввести 0 или отрицательное число, цикл не выполнится ни разу и программа молча напечатала бы Sum = 0: для N = 0 это ещё логично, а для N = -3 бессмысленно. Поэтому добавлены три строки: если n < 1 - сообщить и выйти (return внутри main завершает программу). Такая же проверка есть в задачах 2 и 3. В геометрических задачах слайдов 31-32 требований к знаку чисел в условии нет, проверок там нет.

Задача 2. Сумма ряда дробей 1 + 1/2 + 1/3 + ... + 1/N

Руками, N = 4: копилка 0 - положили 1 - стало 1 - положили 1/2 - стало 1.5 - положили 1/3 - стало 1.8333 - положили 1/4 - стало 2.0833. Всё как в задаче 1, только на шаге k кладём не k, а 1/k.

Файл SumOfFractions.java

```java
import java.util.Locale;
import java.util.Scanner;

public class SumOfFractions {
    public static void main(String[] args) {
        Locale.setDefault(Locale.US);
        Scanner scanner = new Scanner(System.in);

        System.out.print("Enter N: ");
        int n = scanner.nextInt();
        scanner.close();

        if (n < 1) {
            System.out.println("N must be a positive integer.");
            return;
        }

        double sum = 0;
        for (int k = 1; k <= n; k++) {
            sum += 1.0 / k;
        }

        System.out.println("Sum = " + String.format("%.4f", sum));
    }
}
```

Запуск, пример со слайда (N = 4):

```
Enter N: 4
Sum = 2.0833
```

Другие значения (настоящие запуски): N = 1 - Sum = 1.0000; N = 10 - Sum = 2.9290; N = 100 - Sum = 5.1874; N = 1000000 - Sum = 14.3927; N = 0 - сообщение об ошибке.

Главная ловушка - целочисленное деление. Java выбирает вид деления по типам чисел по обе стороны знака /. Если оба числа int, это деление нацело: дробная часть отбрасывается, и 1 / 2 равно 0, 1 / 3 равно 0. Если хотя бы одно из чисел double (например 1.0 / 2), второе автоматически превращается в double, и деление настоящее: получается 0.5. Поэтому в программе написано 1.0 / k, а не 1 / k. Реально: строка sum += 1 / k (без ".0") на N = 4 печатает Sum = 1.0000, потому что получается 1 + 0 + 0 + 0. Заметь: переменная sum при этом всё равно double, но это не спасает - деление 1 / k выполняется в целых числах ещё до того, как результат попадёт в sum. Подсказка слайда "use the double type" как раз про то, что дробным должно быть само деление.

Задача 3. Знакочередующийся ряд 1 - 1/2 + 1/3 - 1/4 + ...

Руками, N = 4: копилка 0 - положили 1 - стало 1 - вычли 1/2 - стало 0.5 - положили 1/3 - стало 0.8333 - вычли 1/4 - стало 0.5833. От задачи 2 отличается только знак: у членов с нечётным номером плюс, с чётным минус (подсказка слайда). Нечётность номера проверяется остатком от деления на 2: k % 2 == 1 значит k нечётное.

Файл AlternatingSeries.java

```java
import java.util.Locale;
import java.util.Scanner;

public class AlternatingSeries {
    public static void main(String[] args) {
        Locale.setDefault(Locale.US);
        Scanner scanner = new Scanner(System.in);

        System.out.print("Enter N: ");
        int n = scanner.nextInt();
        scanner.close();

        if (n < 1) {
            System.out.println("N must be a positive integer.");
            return;
        }

        double sum = 0;
        for (int k = 1; k <= n; k++) {
            if (k % 2 == 1) {
                sum += 1.0 / k;
            } else {
                sum -= 1.0 / k;
            }
        }

        System.out.println("Sum = " + String.format("%.4f", sum));
    }
}
```

Запуск, пример со слайда (N = 4):

```
Enter N: 4
Sum = 0.5833
```

Другие значения (настоящие запуски): N = 1 - Sum = 1.0000; N = 2 - Sum = 0.5000; N = 3 - Sum = 0.8333; N = 10 - Sum = 0.6456; N = 1000000 - Sum = 0.6931.

Последнее число - хороший признак, что знаки расставлены правильно: этот ряд с ростом N приближается к натуральному логарифму двойки, ln 2 = 0.6931... Если бы все члены шли с плюсом, получился бы ряд из задачи 2 (при N = 1000000 - 14.3927).

Слайд 31 - геометрия

Схема одинаковая: прочитать числа (double), подставить в формулы, вывести. Из стандартной библиотеки нужны два помощника: Math.PI (число π с точностью double, руками писать 3.14 не нужно) и Math.sqrt(x) (квадратный корень).

Задача 4. Круг: площадь и длина окружности

Руками, r = 5: длина окружности 2·π·5 = 31.42, площадь π·5·5 = 78.54 (числа со слайда).

Файл CircleCalculator.java

```java
import java.util.Locale;
import java.util.Scanner;

public class CircleCalculator {
    public static void main(String[] args) {
        Locale.setDefault(Locale.US);
        Scanner scanner = new Scanner(System.in);

        System.out.print("Enter r: ");
        double radius = scanner.nextDouble();
        scanner.close();

        double area = Math.PI * radius * radius;
        double circumference = 2 * Math.PI * radius;

        System.out.println("Area = " + String.format("%.2f", area));
        System.out.println("Circumference = " + String.format("%.2f", circumference));
    }
}
```

Запуск, пример со слайда (r = 5):

```
Enter r: 5
Area = 78.54
Circumference = 31.42
```

Другие значения (настоящие запуски): r = 1 - Area = 3.14, Circumference = 6.28; r = 2.5 - Area = 19.63, Circumference = 15.71; r = 0 - Area = 0.00, Circumference = 0.00.

Про radius * radius. В Java знак ^ - это НЕ возведение в степень, а побитовое исключающее ИЛИ. Для double такая запись вообще не компилируется (настоящая ошибка javac: bad operand types for binary operator '^'), а для целых молча считает не то: 5 ^ 2 в Java равно 7, а не 25. Поэтому квадрат пишется как radius * radius (или Math.pow(radius, 2), это тоже 25.0 для радиуса 5).

Задача 5. Прямоугольный треугольник по катетам

Руками, a = 3, b = 4: c² = 9 + 16 = 25, значит гипотенуза c = 5 (знаменитый треугольник 3-4-5). Площадь - половина произведения катетов: 3·4/2 = 6. Периметр: 3 + 4 + 5 = 12.

Файл RightTriangleCalculator.java

```java
import java.util.Locale;
import java.util.Scanner;

public class RightTriangleCalculator {
    public static void main(String[] args) {
        Locale.setDefault(Locale.US);
        Scanner scanner = new Scanner(System.in);

        System.out.print("Enter a: ");
        double legA = scanner.nextDouble();
        System.out.print("Enter b: ");
        double legB = scanner.nextDouble();
        scanner.close();

        double hypotenuse = Math.sqrt(legA * legA + legB * legB);
        double area = legA * legB / 2;
        double perimeter = legA + legB + hypotenuse;

        System.out.println("Hypotenuse = " + String.format("%.2f", hypotenuse));
        System.out.println("Area = " + String.format("%.2f", area));
        System.out.println("Perimeter = " + String.format("%.2f", perimeter));
    }
}
```

Запуск, пример со слайда (a = 3, b = 4):

```
Enter a: 3
Enter b: 4
Hypotenuse = 5.00
Area = 6.00
Perimeter = 12.00
```

Числа те же, что в примере на слайде (5, 6, 12), только с ".00": слайд просит печатать дробные числа с 2-4 знаками после точки.

Другие значения (настоящие запуски): a = 5, b = 12 - Hypotenuse = 13.00, Area = 30.00, Perimeter = 30.00; a = 1, b = 1 - Hypotenuse = 1.41, Area = 0.50, Perimeter = 3.41; a = 2.5, b = 6 - Hypotenuse = 6.50, Area = 7.50, Perimeter = 15.00.

Порядок строк с вычислениями важен: сначала гипотенуза - она нужна для периметра. Катеты читаются как double, а не int: они могут быть дробными (2.5), и та же ловушка целочисленного деления из задачи 2 сработала бы здесь в a * b / 2 - например, 3 * 3 / 2 в целых числах даёт 4, а настоящее значение 4.5 (это проверено: 3 * 3 / 2.0 даёт 4.5).

Задача 6. Расстояние между двумя точками

Руками: A(1, 2), B(4, 6). От A до B нужно пройти 4 - 1 = 3 вправо и 6 - 2 = 4 вверх. Эти два шага - катеты прямоугольного треугольника, а прямая от A до B - его гипотенуза: sqrt(3² + 4²) = 5. То есть это в точности задача 5. Формула d = sqrt((x2 - x1)² + (y2 - y1)²) - просто теорема Пифагора, применённая к разностям координат.

Файл PointDistance.java

```java
import java.util.Locale;
import java.util.Scanner;

public class PointDistance {
    public static void main(String[] args) {
        Locale.setDefault(Locale.US);
        Scanner scanner = new Scanner(System.in);

        System.out.print("Enter x1: ");
        double x1 = scanner.nextDouble();
        System.out.print("Enter y1: ");
        double y1 = scanner.nextDouble();
        System.out.print("Enter x2: ");
        double x2 = scanner.nextDouble();
        System.out.print("Enter y2: ");
        double y2 = scanner.nextDouble();
        scanner.close();

        double dx = x2 - x1;
        double dy = y2 - y1;
        double distance = Math.sqrt(dx * dx + dy * dy);

        System.out.println("Distance d = " + String.format("%.2f", distance));
    }
}
```

Запуск, пример со слайда (A(1, 2), B(4, 6)):

```
Enter x1: 1
Enter y1: 2
Enter x2: 4
Enter y2: 6
Distance d = 5.00
```

Другие значения (настоящие запуски): (0, 0) и (1, 1) - Distance d = 1.41; (-1, -1) и (2, 3) - Distance d = 5.00; одна и та же точка (2, 2) и (2, 2) - Distance d = 0.00.

Слайд 32 - преобразования треугольника

Треугольник задан тремя вершинами A, B, C, у каждой две координаты. Все три преобразования устроены одинаково: одна и та же формула применяется к каждой вершине по очереди. Для трёх однотипных вещей в Java удобны массивы: double[] x = new double[3] - ряд из трёх ячеек для чисел double, где x[0] - координата x вершины A, x[1] - вершины B, x[2] - вершины C (нумерация с нуля); массив y устроен так же. Массив names = {"A", "B", "C"} нужен только для приглашений и вывода. Каждая программа делает три вещи: первым циклом читает три вершины, затем читает параметры преобразования, вторым циклом считает и печатает новые координаты. Штрих в "A'" - обычная математическая запись "A штрих" (вершина A после преобразования); в строке Java он ничем не особенный.

Слайд 32, задача 1. Сдвиг (translation)

Руками: сдвигаем A(1, 1) на вектор (3, 2) - 3 шага вправо и 2 вверх - получаем A'(4, 3). То же самое со всеми вершинами: треугольник переезжает целиком, форма и размер не меняются. Формулы: x' = x + dx, y' = y + dy.

Файл TriangleTranslation.java

```java
import java.util.Locale;
import java.util.Scanner;

public class TriangleTranslation {
    public static void main(String[] args) {
        Locale.setDefault(Locale.US);
        Scanner scanner = new Scanner(System.in);

        String[] names = {"A", "B", "C"};
        double[] x = new double[3];
        double[] y = new double[3];

        for (int i = 0; i < 3; i++) {
            System.out.print("Enter x of " + names[i] + ": ");
            x[i] = scanner.nextDouble();
            System.out.print("Enter y of " + names[i] + ": ");
            y[i] = scanner.nextDouble();
        }
        System.out.print("Enter dx: ");
        double dx = scanner.nextDouble();
        System.out.print("Enter dy: ");
        double dy = scanner.nextDouble();
        scanner.close();

        for (int i = 0; i < 3; i++) {
            double newX = x[i] + dx;
            double newY = y[i] + dy;
            System.out.println(names[i] + "' = (" + String.format("%.2f, %.2f", newX, newY) + ")");
        }
    }
}
```

Запуск, пример со слайда (A(1, 1), B(4, 1), C(2, 3), dx = 3, dy = 2):

```
Enter x of A: 1
Enter y of A: 1
Enter x of B: 4
Enter y of B: 1
Enter x of C: 2
Enter y of C: 3
Enter dx: 3
Enter dy: 2
A' = (4.00, 3.00)
B' = (7.00, 3.00)
C' = (5.00, 5.00)
```

Другие значения (настоящие запуски, тот же треугольник): dx = -1, dy = -1 - A' = (0.00, 0.00), B' = (3.00, 0.00), C' = (1.00, 2.00). Дробные числа: A(0.5, 0.5), B(1.5, 0.5), C(1, 2.5) и вектор (0.25, 0.75) - A' = (0.75, 1.25), B' = (1.75, 1.25), C' = (1.25, 3.25).

Слайд 32, задача 2. Масштабирование (scaling)

Руками: коэффициенты Sx = 2, Sy = 2. Вершина A(1, 1) превращается в A'(2, 2), B(4, 1) - в B'(8, 2), C(2, 3) - в C'(4, 6): все координаты удвоились, треугольник вырос вдвое. Формулы: x' = x · Sx, y' = y · Sy. Из слайда: Sx > 1 - увеличение, Sx = 1 - без изменений, 0 < Sx < 1 - уменьшение. Sx и Sy можно задать разными - тогда треугольник растянется только вдоль одной оси (пример ниже: Sx = 3, Sy = 1).

Важная деталь: координаты умножаются относительно начала координат (0, 0), а не относительно самого треугольника. Поэтому вершины не просто "растут на месте", а ещё и разъезжаются от начала координат: B(4, 1) превратилась в B'(8, 2), то есть уехала от начала вдвое дальше. Формулы со слайда именно такие, ничего лишнего.

Слайд 32, задача 3. Поворот (rotation)

Руками. Точка A(1, 0) лежит на оси X, в одном шаге вправо от начала координат. Поворачиваем её на 90 градусов против часовой стрелки вокруг начала (0, 0): она окажется на оси Y, в одном шаге вверх - A'(0, 1). Точка B(0, 2), два шага вверх, при том же повороте уйдёт влево: B'(-2, 0). Это и есть пример со слайда.

Формулы x' = x · cos(α) - y · sin(α), y' = x · sin(α) + y · cos(α) - короткая запись этого рассуждения. Откуда они берутся: единичный шаг вправо (1, 0) при повороте на угол α попадает в точку (cos α, sin α), а единичный шаг вверх (0, 1) - в точку (-sin α, cos α). Точка (x, y) - это x шагов вправо и y шагов вверх, значит после поворота она станет x · (cos α, sin α) + y · (-sin α, cos α), то есть ровно то, что написано в формулах. Проверка на α = 90 градусов (cos = 0, sin = 1): A(1, 0) даёт x' = 1·0 - 0·1 = 0 и y' = 1·1 + 0·0 = 1, то есть A'(0, 1) - совпало с рассуждением выше. Положительный угол - это поворот против часовой стрелки; поворот по часовой задаётся отрицательным углом.

Файл TriangleRotation.java

```java
import java.util.Locale;
import java.util.Scanner;

public class TriangleRotation {
    public static void main(String[] args) {
        Locale.setDefault(Locale.US);
        Scanner scanner = new Scanner(System.in);

        String[] names = {"A", "B", "C"};
        double[] x = new double[3];
        double[] y = new double[3];

        for (int i = 0; i < 3; i++) {
            System.out.print("Enter x of " + names[i] + ": ");
            x[i] = scanner.nextDouble();
            System.out.print("Enter y of " + names[i] + ": ");
            y[i] = scanner.nextDouble();
        }
        System.out.print("Enter angle in degrees: ");
        double angleDegrees = scanner.nextDouble();
        scanner.close();

        double angleRadians = Math.toRadians(angleDegrees);
        double cosAngle = Math.cos(angleRadians);
        double sinAngle = Math.sin(angleRadians);

        for (int i = 0; i < 3; i++) {
            double newX = x[i] * cosAngle - y[i] * sinAngle;
            double newY = x[i] * sinAngle + y[i] * cosAngle;
            System.out.println(names[i] + "' = (" + format(newX) + ", " + format(newY) + ")");
        }
    }

    private static String format(double value) {
        double cleaned = Math.abs(value) < 1e-9 ? 0.0 : value;
        return String.format("%.2f", cleaned);
    }
}
```

Другой треугольник A(1, 1), B(4, 1), C(2, 3) и угол 30 - A' = (0.37, 1.37), B' = (2.96, 2.87), C' = (0.23, 3.60).

Две ловушки Java в этой задаче (обе подтверждены настоящими запусками).

Первая: Math.sin и Math.cos принимают угол в радианах, а вводится он в градусах. Радиан - это другая единица угла: полный оборот 360 градусов равен 2π радианов (примерно 6.2832), прямой угол 90 градусов равен π/2 (примерно 1.5708). Метод Math.toRadians(90) как раз переводит одно в другое. Если его забыть и передать 90 прямо, программа честно повернёт на 90 РАДИАН - это совсем другой угол. Реально: пример со слайда без перевода в радианы печатает A' = (-0.45, 0.89), B' = (-1.79, -0.90), C' = (-0.90, 1.79) вместо A'(0, 1), B'(-2, 0), C'(0, 2).

Вторая: числа с плавающей точкой считаются с крошечной ошибкой, и Math.cos(Math.toRadians(90)) равен не 0, а 6.123233995736766E-17 (то есть 0.00000000000000006123...). Для расчётов это ничто, но при печати через %.2f маленькое ОТРИЦАТЕЛЬНОЕ число даёт некрасивое "-0.00". Реально, без очистки: для угла 270 печатается A' = (-0.00, -1.00), B' = (2.00, -0.00), C' = (-0.00, -2.00), для угла 360 - A' = (1.00, -0.00), C' = (2.00, -0.00). Поэтому в программе есть маленький метод format: если число по модулю меньше 1e-9 (то есть 0.000000001), оно считается нулём. Порог выбран так, чтобы быть заведомо больше вычислительного шума (порядка 1e-16) и заведомо меньше того, что вообще видно при печати с двумя знаками (0.005). Запись условие ? 0.0 : value читается как "если условие верно - взять 0.0, иначе оставить value".

Частые ошибки (сводка)

- Целочисленное деление: 1 / k при целом k даёт 0 (задачи 2 и 3). Нужно 1.0 / k. Настоящий вывод ошибочной версии: Sum = 1.0000 вместо 2.0833 для N = 4.
- Переполнение int: сумма 1..N при больших N выходит за 2147483647 и молча искажается (задача 1). Нужно long. Настоящий вывод ошибочной версии: Sum = 705082704 вместо 5000050000 для N = 100000.
- Градусы вместо радиан: Math.sin/Math.cos ждут радианы, нужен Math.toRadians (слайд 32, поворот).
- "-0.00" при печати крошечных отрицательных чисел (поворот) - лечится очисткой шума, как в методе format выше.
- Знак ^ в Java - это XOR, а не степень: r ^ 2 для double не компилируется, для int даёт 7 вместо 25. Квадрат - r * r.
- Локаль. На компьютерах с русской или казахской локалью Java считает разделителем дробной части запятую. Настоящие проверки на этом Mac (у него локаль en_KZ, где точка работает, поэтому дома проблему легко не заметить): под ru_RU, kk_KZ и ru_KZ String.format("%.4f", 2.083333) печатает 2,0833, а Scanner.nextDouble() на вводе 2.5 падает с java.util.InputMismatchException. Программа CircleCalculator без строки Locale.setDefault(Locale.US) под ru_RU: на вводе 2.5 - Exception in thread "main" java.util.InputMismatchException; на вводе 2,5 - Area = 19,63, Circumference = 15,71; на вводе 5 - Area = 78,54 (запятая вместо точки в выводе). С этой строкой (итоговая версия) под ru_RU на вводе 2.5 программа работает и печатает Area = 19.63, Circumference = 15.71. Обратная сторона: дробные числа теперь нужно вводить через точку - на вводе 2,5 итоговая версия падает с InputMismatchException.
- Вместо числа набрана буква или пустая строка - Scanner бросает InputMismatchException. Обработка таких ошибок на слайдах не требуется (исключения - тема недели 9).
- Имя файла и имя public-класса не совпали - javac откажется компилировать (см. lectures/01).
