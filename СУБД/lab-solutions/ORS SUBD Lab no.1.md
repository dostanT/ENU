Microsoft SQL Server. Лабораторная 1. Введение в SQL. Дистрибутивы.
Установка Microsoft SQL Server

Важно сразу: в этой лабе нет ни одной строчки кода - вся она про то,
чтобы покликать по графическим утилитам SQL Server Configuration
Manager и SQL Server Management Studio на РЕАЛЬНОЙ установленной
Microsoft SQL Server 2008 и записать, что там видно. В этом окружении
(macOS) MS SQL Server нет и поставить неоткуда (см. раздел
"ИСТОЧНИКИ ПО КУРСУ" корневого CLAUDE.md про платформу этого курса).
Поэтому дальше - объяснение каждого шага и что он означает, но
КОНКРЕТНЫЕ значения для отчёта (список служб, номер порта, корневой
каталог сервера, число процессоров и т.п.) зависят от твоей реальной
установки и взять их неоткуда, кроме как посмотреть самому на
лабораторном компьютере. Выдумывать эти значения я не буду - это
означало бы выдать несуществующие данные за реальное наблюдение.

Задание 1. Изучить утилиту SQL Server Configuration Manager

Механизм: SQL Server Configuration Manager - это отдельная утилита
Windows (не часть Management Studio), которая управляет службами MS
SQL Server и сетевыми настройками подключения к нему, примерно как
обычная утилита "Службы" (services.msc) в Windows, но со знанием
специфики именно SQL Server.

Что нужно сделать и записать в отчёт:
- Список служб, запущенных на сервере (видно в самом Configuration
  Manager, узел SQL Server Services). Типичные службы MS SQL Server
  2008: сам движок (SQL Server, он же MSSQLSERVER или именованный
  экземпляр), SQL Server Agent (планировщик заданий), SQL Server
  Browser (помогает клиентам найти именованные экземпляры по сети) -
  но точный список и их состояние (запущена/остановлена) - только по
  факту с твоей машины.
- Параметры запуска служб MS SQL Server - через утилиту "Службы"
  (Панель управления - Администрирование) или через тот же
  Configuration Manager, если доступа к "Службам" нет.
- Сетевые библиотеки (протоколы) на стороне сервера - узел SQL Server
  Network Configuration. Три классических протокола: Shared Memory
  (для подключений с того же самого компьютера, самый быстрый, но не
  работает по сети), Named Pipes (сетевой протокол поверх SMB,
  исторически из локальных сетей Windows) и TCP/IP (обычный сетевой
  протокол, нужен почти всегда, если клиент и сервер - разные машины).
  Какие из них включены (Enabled) - видно прямо в списке в
  Configuration Manager.
- Сетевые библиотеки на стороне клиента - узел SQL Native Client
  Configuration - Client Protocols, тот же список протоколов, но уже
  для того, как ЭТОТ компьютер подключается к другим SQL-серверам.

Задание 2. Создать псевдоним сервера (alias) для клиентских подключений

Механизм: псевдоним (alias) - это просто удобное локальное имя,
которое клиент подставляет вместо реального сетевого имени сервера и
протокола подключения, чтобы не вводить длинные настройки каждый раз.
Создаётся в SQL Native Client Configuration - Aliases (правая кнопка -
New Alias), задаётся имя (в задании - MyServ), протокол (TCP/IP) и
настоящее сетевое имя компьютера с MS SQL Server.

Что нужно сделать и записать в отчёт:
- Сетевое имя компьютера, на котором установлен MS SQL Server -
  смотрится в свойствах системы Windows (Мой компьютер - Свойства)
  или командой `hostname` в командной строке - опять же, конкретное
  значение только с реальной машины.
- Номер порта для TCP/IP-подключения: по умолчанию MS SQL Server
  слушает TCP-порт 1433 для дефолтного (безымянного) экземпляра. Если
  на сервере настроен именованный экземпляр или порт сознательно
  сменили из соображений безопасности - будет другое число, это видно
  в свойствах протокола TCP/IP в Configuration Manager (вкладка IP
  Addresses, параметр TCP Port). Указывать порт нужно, потому что
  клиент должен знать, на какой именно "дверь" сервера стучаться -
  без номера порта TCP-подключение установить нельзя, это часть
  адреса наравне с именем машины.

Задание 3. Установить соединение с SQL-сервером

Механизм: SQL Server Management Studio (SSMS) - основной графический
инструмент администратора/разработчика для работы с MS SQL Server:
пишешь запросы, смотришь структуру баз через Object Explorer,
настраиваешь сервер через диалоги свойств.

Что нужно сделать:
- Подключиться под именем MyServ (тем самым alias из задания 2),
  аутентификация - "SQL Server Authentication", учётная запись `sa`
  (системный администратор SQL Server, встроенная учётная запись,
  создаётся автоматически при установке), пароль в задании указан
  пустым - это нормально для учебного стенда, но крайне небезопасно
  для реального сервера в проде.
- Новый запрос - кнопка New Query, открывает вкладку с тремя частями:
  заголовок (сервер/база/пользователь), область для ввода запроса, и
  область результатов (переключается между Messages - обычный текст, и
  Results - таблица).
- Команда версии сервера:

```sql
SELECT @@version
```

  `@@version` - системная переменная (не функция, отсюда `@@`, а не
  обычная одна `@` для пользовательской переменной), возвращает
  текстовую строку с версией MS SQL Server, версией ОС и датой сборки.
  Результат текстовый - значит смотреть его нужно на вкладке Messages,
  а не Results.
- F5 (Query - Execute) запускает запрос целиком; Ctrl+F5 (Query -
  Parse) только проверяет синтаксис, ничего не выполняя - полезно,
  чтобы не гонять реальный запрос, если просто хочешь проверить, что
  не опечатался.
- Список баз данных - в Object Explorer, узел Databases. Системные
  базы MS SQL Server создаются автоматически при установке и есть на
  любом сервере: master (системные настройки самого сервера), model
  (шаблон для новых баз - всё, что в ней есть, копируется в каждую
  новую БД при создании), msdb (данные для SQL Server Agent -
  расписания заданий, история бэкапов), tempdb (временные объекты,
  очищается при каждом перезапуске сервера). Всё остальное в списке -
  уже пользовательские базы (в этом курсе, например, AdventureWorks2008
  - см. lab-solutions/ORS SUBD Lab no.2.md).

Задание 4. Изучить параметры конфигурации MS SQL Server

Механизм: свойства сервера (правая кнопка на сервере в Object Explorer
- Properties) - это графическая обёртка над системными хранимыми
процедурами настройки сервера; смысл получить те же настройки можно
и через код (`sp_configure`), но задание просит именно через диалог.

Что означает каждая вкладка:
- General - версия ОС, объём памяти, число процессоров, параметры
  запуска службы - общая информация о системе.
- Memory - управление памятью под MS SQL Server: либо динамическое
  (сервер сам решает, сколько брать, в зависимости от нагрузки), либо
  фиксированный размер (заранее заданный жёсткий лимит).
- Security - тип аутентификации пользователей (только Windows, либо
  Windows + SQL Server, "смешанный режим" - именно смешанный режим и
  нужен, чтобы вообще можно было зайти под `sa`, как в задании 3) и
  параметры аудита доступа к серверу; можно также задать, под какой
  учётной записью ОС запускается сама служба MSSQLServer.
- Connections - настройки клиентских подключений, включая максимальное
  число одновременных пользователей. Если стоит 0 - лимит фактически
  снят, сервер разрешает до 32767 подключений (это техническое
  ограничение самого MS SQL Server, а не "без лимита").
- Advanced - разные общие настройки сервера, например язык сообщений
  по умолчанию или интерпретация двух последних цифр года (Y2K-style
  настройка для дат с двузначным годом).
- Database Settings - настройки для НОВЫХ баз данных по умолчанию:
  параметры индексов, устройства для резервного копирования, время на
  восстановление базы.

Что нужно записать в отчёт (конкретные значения - только с реальной
установленной MS SQL Server, здесь не воспроизводимо): корневой
каталог сервера, число процессоров в системе, тип аутентификации,
максимальное число поддерживаемых пользователей.
