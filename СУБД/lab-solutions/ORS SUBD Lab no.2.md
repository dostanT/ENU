Задание 2. Определить, есть ли у пользователя право SELECT на таблицу Product

Механизм (код дан в самом задании, здесь - объяснение, а не решение с
нуля): `OBJECT_ID('production.product')` переводит имя таблицы (схема
"production", таблица "product") в её внутренний числовой
идентификатор - большинство системных функций работают именно с
идентификаторами, а не с текстовыми именами напрямую. Дальше функция
`PERMISSIONS(...)` возвращает 32-битную маску: каждый бит - это
да/нет на конкретное действие, а КАКОЕ именно действие означает каждый
бит, зависит от того, как вызвана сама функция - без параметров (права
в текущей базе вообще), с одним параметром object_id (права на объект
целиком) или с двумя object_id+атрибут (права на конкретное поле).
Для варианта "один параметр" нулевой бит (значение 1) - это право
SELECT ALL. Чтобы проверить именно нулевой бит, используется побитовое
И (`&`): `маска & 1` даёт 1 только если нулевой бит замаскированной
величины установлен, иначе 0.

```sql
IF PERMISSIONS(OBJECT_ID('production.product')) & 1 = 1
    PRINT 'Have the right to select'
ELSE
    PRINT 'No selection rights'
```

PRINT вместо SELECT здесь потому, что PRINT выводит просто текст на
вкладку Messages, а SELECT - таблицу с результатом на вкладку Results;
для простого да/нет-сообщения PRINT нагляднее.

Не проверено выполнением: функция PERMISSIONS зависит от того, какие
права реально выданы текущему пользователю на сервере, и от наличия
таблицы production.product в базе - ни того, ни другого здесь нет.

Задание 3. Имя компьютера, укороченное если длиннее 9 букв

Механизм (код дан в задании): `HOST_NAME()` возвращает имя компьютера,
с которого установлено соединение. `DATALENGTH()` возвращает длину
значения В БАЙТАХ, а не в символах - и это специально подчёркнуто в
задании: `HOST_NAME()` возвращает тип `nvarchar` (Unicode-строка), где
на каждый символ уходит 2 байта, поэтому длину в байтах нужно поделить
на 2, чтобы получить длину в символах.

```sql
IF (DATALENGTH(HOST_NAME()) / 2 > 9)
    SELECT LEFT(HOST_NAME(), 6) + '...'
ELSE
    SELECT HOST_NAME()
```

Не проверено выполнением: имя компьютера зависит от конкретной
машины, на которой подключение к серверу.

Задание 4. Посчитать число цифр в числе

Механизм (код дан в задании, база для Независимой работы 1 ниже):
классический приём "делим на 10, пока не останется 0, считаем сколько
раз поделили" - каждое деление на 10 (целочисленное) отбрасывает
последнюю цифру числа, поэтому число делений равно числу цифр. Отдельный
IF нужен только потому, что для 0 цикл `WHILE (@num <> 0)` не
выполнится вообще ни разу (0 не равно 0 - ложь), а у числа 0 всё равно
есть 1 цифра, это частный случай, который иначе будет посчитан
неправильно (0 цифр вместо 1).

```sql
DECLARE @num int, @cnt int
SET @num = 19
IF (@num = 0) SET @cnt = 1
ELSE
BEGIN
    SET @cnt = 0
    WHILE (@num <> 0)
    BEGIN
        SET @cnt = @cnt + 1
        SET @num = @num / 10
    END
END
SELECT @cnt AS 'Number of digits'
```

Самостоятельная работа

1. Оптимизировать задание 4: убрать IF, оставить только WHILE, чтобы
работало для нуля, положительных и отрицательных чисел

Механизм: чтобы не терять 0 без отдельного IF - взять модуль числа
(ABS, заодно решает и отрицательные числа) и начинать счётчик не с 0,
а сразу с 1, а цикл гонять, пока в числе ЕЩЁ ЕСТЬ вторая и следующие
цифры (`@num >= 10`), а не пока число не станет нулём. Тогда для 0
цикл не выполнится ни разу и счётчик останется 1 - правильный ответ без
единого IF.

```sql
DECLARE @num INT, @cnt INT
SET @num = -19
SET @num = ABS(@num)
SET @cnt = 1
WHILE (@num >= 10)
BEGIN
    SET @num = @num / 10
    SET @cnt = @cnt + 1
END
SELECT @cnt AS 'Number of digits'
```

Проверено (python3, та же логика): 0 -> 1 цифра, 5 -> 1, 19 -> 2, -19
-> 2, 100000 -> 6, -7 -> 1. Все случаи, которые требовало задание (0,
положительные, отрицательные), совпадают с ожидаемым.

3. Перевод фунтов в килограммы (1 фунт = 453.6 г)

Механизм: переводим фунты сразу в граммы (умножаем на 453.6), потом
делим нацело на 1000, чтобы получить целые килограммы, а остаток от
этого деления - оставшиеся граммы.

```sql
DECLARE @lbs FLOAT, @total_g FLOAT, @kg INT, @g INT
SET @lbs = 3.3
SET @total_g = @lbs * 453.6
SET @kg = FLOOR(@total_g / 1000)
SET @g = FLOOR(@total_g - @kg * 1000)
SELECT CAST(@lbs AS VARCHAR) + ' lb(s) is ' + CAST(@kg AS VARCHAR) + ' kg ' + CAST(@g AS VARCHAR) + ' g.'
```

Проверено (python3, та же арифметика): 3.3 lb(s) is 1 kg 496 g. -
совпадает ровно с примером из задания. Ещё проверки: 10 lb(s) is 4 kg
536 g., 0.5 lb(s) is 0 kg 226 g.

5. Сколько часов и минут прошло с момента запуска служб MS SQL Server

Механизм: у MS SQL Server есть системное представление
`sys.dm_os_sys_info` (DMV - Dynamic Management View, показывает
текущее состояние работающего сервера), в котором есть поле
`sqlserver_start_time` - момент последнего старта службы. Дальше
`DATEDIFF` считает разницу между этим моментом и текущим временем в
минутах, а часы и минуты получаются обычным делением с остатком на 60.

```sql
DECLARE @start DATETIME, @diffMinutes INT
SELECT @start = sqlserver_start_time FROM sys.dm_os_sys_info
SET @diffMinutes = DATEDIFF(MINUTE, @start, GETDATE())
SELECT (@diffMinutes / 60) AS Hours, (@diffMinutes % 60) AS Minutes
```

Не проверено выполнением: результат существует только у реально
работающего сервера, зависит от момента его последнего запуска.

6. Является ли текущий год високосным

Механизм: стандартное правило григорианского календаря - год
високосный, если делится на 4, кроме тех случаев, когда делится на
100, но тогда всё равно високосный, если делится на 400 (поэтому 1900
- не високосный, а 2000 - високосный).

```sql
DECLARE @year INT
SET @year = YEAR(GETDATE())
IF (@year % 4 = 0 AND (@year % 100 <> 0 OR @year % 400 = 0))
    PRINT 'Leap year'
ELSE
    PRINT 'Not a leap year'
```

Проверено (python3, то же правило): 2024 -> високосный, 2025 -> нет,
2026 -> нет, 1900 -> нет, 2000 -> високосный - все совпадает с
ожидаемым по календарю.

7. Сумма чисел в заданной строке символов

Формулировка неоднозначна - здесь взят более содержательный и
распространённый вариант этого классического задания: в строке ищутся
ПОСЛЕДОВАТЕЛЬНОСТИ ЦИФР подряд (например "12" в "abc12de34" - это одно
число 12, а не 1+2), каждая такая последовательность превращается в
своё число, и эти числа складываются.

Механизм: идём по строке посимвольно; пока символ - цифра, копим его в
строку-накопитель @cur; как только встретили НЕ цифру (или строка
кончилась) - если накопитель не пуст, превращаем его в число и
прибавляем к общей сумме, накопитель очищаем.

```sql
DECLARE @s VARCHAR(200), @i INT, @len INT, @ch CHAR(1), @cur VARCHAR(20), @total INT
SET @s = 'abc12de34'
SET @i = 1
SET @len = LEN(@s)
SET @cur = ''
SET @total = 0
WHILE (@i <= @len)
BEGIN
    SET @ch = SUBSTRING(@s, @i, 1)
    IF (@ch >= '0' AND @ch <= '9')
        SET @cur = @cur + @ch
    ELSE
    BEGIN
        IF (@cur <> '')
        BEGIN
            SET @total = @total + CAST(@cur AS INT)
            SET @cur = ''
        END
    END
    SET @i = @i + 1
END
IF (@cur <> '')
    SET @total = @total + CAST(@cur AS INT)
SELECT @total AS 'Sum of numbers'
```

Проверено (python3, та же логика): 'abc12de34' -> 46 (12+34), 'a1b2c3'
-> 6 (1+2+3, тут каждая цифра сама по себе - отдельное число), 'no
digits here' -> 0, '007 and 42!' -> 49 (7+42, ведущие нули в числе не
меняют его значение).

8. Стоимость отправки телеграммы (33 копейки за слово)

Механизм: строка заканчивается точкой (это конец телеграммы, не часть
текста), слов может разделять любое число пробелов подряд. Идём по
строке посимвольно и отслеживаем состояние "я сейчас внутри слова или
между словами" (@inWord) - слово считается НОВЫМ только в момент
перехода из "между словами" в "внутри слова", это и защищает от
повторного счёта при нескольких пробелах подряд.

```sql
DECLARE @line VARCHAR(500), @i INT, @len INT, @ch CHAR(1), @inWord BIT, @words INT, @kop INT, @rub INT
SET @line = 'hello   world  this is  a test.'
SET @i = 1
SET @len = LEN(@line)
SET @inWord = 0
SET @words = 0
WHILE (@i <= @len)
BEGIN
    SET @ch = SUBSTRING(@line, @i, 1)
    IF (@ch <> ' ' AND @ch <> '.')
    BEGIN
        IF (@inWord = 0)
        BEGIN
            SET @words = @words + 1
            SET @inWord = 1
        END
    END
    ELSE
        SET @inWord = 0
    SET @i = @i + 1
END
SET @kop = @words * 33
SET @rub = @kop / 100
SET @kop = @kop % 100
SELECT @words AS Words, @rub AS Rub, @kop AS Kop
```

Проверено (python3, та же логика подсчёта слов и денег): "hello
world this is a test." (6 слов, лишние пробелы) -> 6 слов, 1 руб. 98
коп.; "one." -> 1 слово, 0 руб. 33 коп.; строка с одиночными буквами
через много пробелов ("a b c d e.") -> 5 слов, 1 руб. 65 коп. -
подсчёт слов не путается от количества пробелов между ними.

9. Шифр Цезаря

Механизм: каждая буква сдвигается на фиксированное число позиций по
кругу внутри своего алфавита (28 сдвигов для латиницы возвращают на то
же место, потому что букв 26 - это и есть "по кругу", операция
взятия остатка `% 26`). Регистр (заглавная/строчная) и все не-буквы
(знаки препинания, пробелы) остаются без изменений - для этого код
отдельно проверяет диапазон ASCII-кодов заглавных (65-90) и строчных
(97-122) латинских букв.

```sql
DECLARE @text VARCHAR(500), @shift INT, @i INT, @len INT, @ch CHAR(1), @code INT, @result VARCHAR(500)
SET @text = 'Hello, World!'
SET @shift = 3
SET @i = 1
SET @len = LEN(@text)
SET @result = ''
WHILE (@i <= @len)
BEGIN
    SET @ch = SUBSTRING(@text, @i, 1)
    SET @code = ASCII(@ch)
    IF (@code BETWEEN 65 AND 90)
        SET @result = @result + CHAR(65 + ((@code - 65 + @shift) % 26 + 26) % 26)
    ELSE IF (@code BETWEEN 97 AND 122)
        SET @result = @result + CHAR(97 + ((@code - 97 + @shift) % 26 + 26) % 26)
    ELSE
        SET @result = @result + @ch
    SET @i = @i + 1
END
SELECT @result
```

Двойное `+ 26) % 26` в конце - защита от отрицательного сдвига: в
T-SQL, как и во многих языках, остаток от деления отрицательного числа
может получиться отрицательным, а прибавка 26 перед повторным `% 26`
гарантирует положительный результат в любом случае (и для
расшифровки тем же кодом с отрицательным @shift).

Проверено (python3, тот же алгоритм): 'Hello, World!' со сдвигом 3 ->
'Khoor, Zruog!', и обратный сдвиг -3 применённый к результату
возвращает ровно исходную строку 'Hello, World!' - шифрование и
расшифровка согласованы. Пример дан для латиницы - для кириллицы
понадобится тот же приём, но с диапазоном кодов кириллических букв (в
Unicode они тоже идут подряд, но не 26, а 33 буквы, включая или не
включая ё по договорённости).

10. Персональное число по ФИО

Механизм: буквам русского алфавита сопоставляется номер по порядку (а
- 1, б - 2, ..., я - 33), номера всех букв ФИО складываются, и если
сумма не однозначное число - складываются уже цифры этой суммы, и так
до тех пор, пока не останется одна цифра (это классическая операция
"цифровой корень" числа). Поиск номера буквы в T-SQL делается через
CHARINDEX - позицию буквы в строке-алфавите.

```sql
DECLARE @fio VARCHAR(200), @alphabet VARCHAR(33), @i INT, @len INT, @ch VARCHAR(1), @total INT, @n INT, @s INT
SET @fio = 'Иванов Иван Иванович'
SET @alphabet = 'абвгдеёжзийклмнопрстуфхцчшщъыьэюя'
SET @fio = LOWER(@fio)
SET @i = 1
SET @len = LEN(@fio)
SET @total = 0
WHILE (@i <= @len)
BEGIN
    SET @ch = SUBSTRING(@fio, @i, 1)
    IF (CHARINDEX(@ch, @alphabet) > 0)
        SET @total = @total + CHARINDEX(@ch, @alphabet)
    SET @i = @i + 1
END
WHILE (@total >= 10)
BEGIN
    SET @s = 0
    SET @n = @total
    WHILE (@n > 0)
    BEGIN
        SET @s = @s + @n % 10
        SET @n = @n / 10
    END
    SET @total = @s
END
SELECT @total AS 'Personality number'
```

Проверено (python3, тот же алфавит и та же логика цифрового корня):
"Иванов Иван Иванович" -> 7, "Турлыбек Достан" -> 8.
