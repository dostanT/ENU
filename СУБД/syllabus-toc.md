# Силлабус курса — DBT 3308, Объектно-реляционные СУБД (ENU)

Справочник по `syllabus/Объектно реляционные СУБД.pdf` (61 стр., силлабус
ЕНУ седьмого издания). Курс: **DBT 3308 — Object-Relational Database

программа 6B06104 «Computer Engineering and Software». 3 курс, 5
семестр, 7 ECTS. 30 ч лекций, 15 ч практик, 30 ч лабораторных, 135 ч
СРС.

## Важно: платформа курса — Microsoft SQL Server, не PostgreSQL

Лабораторные работы этого курса написаны **конкретно под Microsoft SQL
Server 2008** (SQL Server Management Studio, T-SQL, учебная база
AdventureWorks2008) — это видно из текста лаб (`sp_addlogin`,
`sp_helpdb`, `BACKUP DATABASE`, `DECLARE @var`, синтаксис хранимых
процедур и т. д.), а не из общих формулировок силлабуса. В этом
окружении есть PostgreSQL (`psql`) и `sqlite3`, но **не** MS SQL Server
и не MySQL, и Docker тоже не установлен (значит поднять настоящий
MS SQL Server в контейнере сейчас нельзя, хотя это возможно в
принципе — образ `mcr.microsoft.com/mssql/server` существует и под
Apple Silicon). Это та же ситуация, что с Win32 API в курсе
«Системное программирование» — курс учит платформенно-специфичной
вещи, которой нет на macOS пользователя.

Что с этим делать при разборе тем и лаб этого курса:
- Переносимый / стандартный SQL (обычные SELECT, JOIN, GROUP BY,
  подзапросы, CREATE TABLE без специфичных типов) — реально проверяй
  через `psql` или `sqlite3`, это работает одинаково или почти
  одинаково.
- T-SQL-специфичные вещи (хранимые процедуры в синтаксисе `CREATE
  PROCEDURE ... AS`, системные `sp_*` процедуры, `PRINT`, `TOP` вместо
  `LIMIT`, `IDENTITY` вместо `SERIAL`, `DATALENGTH`, работа с
  логинами/ролями сервера через `sp_addlogin`/`GRANT` в стиле MS SQL)
  — это нельзя проверить выполнением в этом окружении. Объясняй по
  документации T-SQL, явно говори, что не проверено выполнением, и по
  возможности показывай рядом, как то же самое выглядит в PostgreSQL
  (ближайший из доступных здесь диалектов), если это помогает
  пользователю понять разницу.

## Модуль 1 — Введение в управление данными (недели 1-7)

1. Введение. Предмет курса. Что такое данные. Базовые определения — стр. лекций 1
2. Три базовые модели данных. Реляционные базы данных (Э. Кодд, реляционная модель) — стр. лекций 1
3. Этапы проектирования реляционных БД — стр. лекций 2
4. SQL, базовые команды (CREATE/USE/SOURCE/DROP/SHOW/CREATE TABLE, ограничения PRIMARY KEY/FOREIGN KEY) — стр. лекций 2-3
5. Однострочные функции (single-row vs multi-row функции в SELECT) — стр. лекций 3
6. Получение данных из нескольких таблиц. JOIN (INNER/LEFT OUTER/RIGHT OUTER/FULL OUTER/CROSS) — стр. лекций 3
7. Итоговые данные через групповые функции (SUM, AVG, COUNT, DISTINCT) — стр. лекций 3-4

## Лабораторные работы (1:1 с неделями, детальные инструкции в PDF)

1. Установка и настройка Microsoft SQL Server 2008 (SQL Server Configuration Manager, протоколы подключения, alias сервера)
2. Введение в T-SQL: функция Permissions, работа с битовой маской прав, HOST_NAME, DATALENGTH, счётчик цифр числа через WHILE
3. Выборка данных (Lab #3): SELECT из AdventureWorks2008, LIKE, IN, IS NULL, переименование колонок через AS
4. Хранимые процедуры: CREATE PROCEDURE, параметры OUTPUT, EXEC
5. Система безопасности MS SQL Server: sp_addlogin, sp_addsrvrolemember, sp_adduser, GRANT/DENY, роли сервера и БД
6. Управление базой данных: CREATE DATABASE с файлами данных/лога, BACKUP DATABASE, sp_adddumpdevice
7. Выборка из нескольких таблиц: INNER/LEFT/RIGHT/CROSS JOIN на AdventureWorks2008 и Northwind
8. Аналитическая выборка: агрегатные функции, GROUP BY, вложенные подзапросы
9. Представления (VIEW): вертикальная и горизонтальная фильтрация данных
10. Проектирование БД: логическое и физическое моделирование, 4 группы правил целостности (домен/сущность/ссылочная/пользовательская), CONSTRAINT (PRIMARY KEY/FOREIGN KEY/UNIQUE/DEFAULT/CHECK)
11. Управление данными: INSERT (в т.ч. INSERT...SELECT), BULK INSERT из текстового файла, UPDATE с подзапросом, DELETE, разница DELETE/TRUNCATE

По остальным неделям (12-15: проектирование в Erwin Studio, UML-диаграммы, введение в .NET) в PDF детальных инструкций лабы не было в прочитанном диапазоне — только тема в общей таблице (см. выше, недели 13-15 в общей таблице лабораторных).

## Самостоятельная работа студента (СРС/IWS) — важно: объектно-реляционный акцент

В отличие от лекций и лаб (которые почти всю дорогу — обычная
реляционная теория и чистый T-SQL), 15 заданий СРС прицельно про
**объектно-реляционную** часть названия курса:

1. Сходства/различия подходов (эссе)
2. Поддержка объектных расширений в PostgreSQL и Oracle (мини-исследование)
3. Стандарты и их поддержка в популярных СУБД (эссе)
4. Разработка объектной схемы для предметной области, например системы бронирования (практическое задание)
5. Наследование и полиморфизм в объектных типах БД (эссе)
6. Бизнес-логика через объектные методы (практическое задание)
7. Преобразование UML class diagram в объектно-реляционные структуры (практическое задание)
8. Проблемы использования объектов в реляционной СУБД (мини-исследование)
9. Создание триггеров для объектов (практическое задание)
10. Организация доступа к вложенным объектам в SQL-запросах (эссе)
11. Стресс-тестирование обычных и объектных схем (эссе)
12. Объектно-реляционные возможности IBM Db2 и MS SQL Server (мини-исследование)
13. ORM-подходы (SQLAlchemy, Hibernate) и прямой вызов объектов (эссе)
14. План миграции, потенциальные сложности (практическое задание)
15. Мини-проект: объектно-реляционная модель БД для интернет-магазина/библиотеки/CRM (практическое задание)

Формат эссе — 10-12 страниц, интервал 1.0, структура Введение/Основная
часть/Заключение/Список литературы.

## Контроль

Рубежный контроль 1 и 2 — коллоквиум. Итоговый контроль — устный
экзамен. В PDF есть готовый банк вопросов (~60 вопросов на два
рубежных контроля + почти тот же список на итоговый) — темы: архитектура
БД, независимость данных, инфологическая/даталогическая/физическая
модели, нормальные формы (1NF-3NF, Бойса-Кодда), реляционная алгебра,
структура SQL, виды JOIN (внутреннее/внешнее/левое/правое/полное/
декартово/тета/естественное), простые и связанные подзапросы,
рекурсивные запросы. Если пользователь попросит подготовиться к
коллоквиуму/экзамену — можно использовать эти вопросы как чек-лист тем.

Мелкая неточность в самом PDF: вопрос 29 банка вопросов спрашивает
«какие типы данных есть в MySQL», хотя весь практический курс — MS SQL
Server, а не MySQL. Похоже на копипаст из шаблона другого курса —
не повод считать, что курс использует MySQL.
