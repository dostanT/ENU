Карта проекта

Это краткое описание того, что лежит в каждом файле проекта — чтобы не перечитывать всё заново для контекста. Обновляется при каждом новом файле в lectures, solutions, lab-solutions, а также когда в tasks, labs, teacher-lectures или syllabus появляется файл, которого здесь ещё нет.

Корень проекта

CLAUDE.md - правила работы над проектом: стиль объяснений (ELI5), структура папок, форматирование файлов, как проверять SQL, как вести MAP.md. Роль обновлена под реальный силлабус курса (DBT 3308, ЕНУ, объектно-реляционные СУБД, 15 недель в 2 модулях, практика на Microsoft SQL Server). Учебника (отдельной книги) пока нет - см. в CLAUDE.md раздел "ИСТОЧНИКИ ПО КУРСУ".

syllabus-toc.md - разбор силлабуса по неделям: темы модуля 1 (недели 1-7, реляционная теория и основы SQL) и модуля 2 (недели 8-15, сложные запросы/DML/DDL/нормализация/объекты БД/OLAP), детали всех 11 прочитанных лабораторных (все на Microsoft SQL Server 2008 / T-SQL / AdventureWorks2008), список 15 тем самостоятельной работы (объектно-реляционный акцент - ORM, наследование/полиморфизм в БД, сравнение СУБД), список литературы, банк вопросов к коллоквиумам и экзамену. Отдельно отмечает, что практика курса - именно MS SQL Server, а в этом окружении есть только PostgreSQL/sqlite3, и как с этим работать.

lectures

01-02-vvedenie-v-bazy-dannyh-i-modeli-dannyh.md - конспект по темам 1-2 (обе на "стр. лекций 1" силлабуса, отсюда двойной номер). Что такое БД и 6 характеристик, классификация БД по 6 осям, историческая эволюция моделей данных (иерархическая/сетевая/реляционная) с объяснением ПОЧЕМУ реляционная победила (декларативные запросы через совпадение ключей вместо явных путей + математическое обоснование), ключевые понятия реляционной модели (отношение/кортеж/атрибут, первичный/внешний ключ, на примере students/enrollments), СУБД и её функции (управление данными, ACID на примере банковского перевода, контроль параллельности, восстановление после сбоев), трёхуровневая архитектура ANSI/SPARC, современные тренды (NoSQL по видам, NewSQL).

03-arhitektura-subd-i-ordsubd.md - конспект по LECTURE 3_eng.pdf преподавателя ("Object-Relational DBMS Architecture"). Номер файла - по номеру лекции преподавателя, а не темы силлабуса (тема 3 силлабуса называется "Этапы проектирования реляционных БД" - не совпадает с содержанием). Требования к архитектуре СУБД (чек-лист); централизованные/распределённые БД и файл-сервер/клиент-сервер архитектуры (аналогии: shared Excel на сетевом диске против Google Таблиц); 6 внутренних компонентов СУБД (Transaction Manager, Query Optimizer, Parser, Buffer Manager, Storage Engine, Log Manager/WAL); трёхуровневая архитектура ANSI/SPARC (аналогия с рестораном - меню/рецептурный справочник/склад) и логическая/физическая независимость данных; зачем появились ОРСУБД (impedance mismatch на примере Java-объекта со списком курсов, сложные типы данных); объектные БД как отдельное явление от ОРСУБД; расширяемость и 4 столпа ООП в ОРСУБД (UDT со структурными типами и коллекциями, методы/инкапсуляция, наследование таблиц и типов, полиморфизм на примере оператора +); архитектурные компоненты ОРСУБД (UDT Manager, Methods/ADT/O-R Mapping/оптимизатор) плюс 3 расширения (расширенный каталог, объектно-ориентированный оптимизатор, расширяемая индексация GiST/GIN - с форвард-ссылкой на тему 14); сравнение RDBMS/ОРСУБД - лекция просит студента самому составить таблицу, готового содержания нет, оставлены только измерения для сравнения без выдуманных значений; плюсы/минусы ОРСУБД; заключение (успешный компромисс, устоял против объектных БД в 2000х и NoSQL в 2010х). Дополнен ответами на все 10 контрольных вопросов лекции (22.09.2026), включая сравнение RDBMS/ОРСУБД по критериям из вопроса 10 - на этот раз выполнено по-настоящему, раз попросили ответить на вопросы, а не просто законспектировать лекцию.

04-sql-naznachenie-istoriya-i-kategorii-komand.md - расширен 29.09.2026 материалом Lecture 4_eng.pdf, раньше был только обзор по Lecture 2. Теперь конспект по теме 4 целиком: зачем нужен SQL (общий язык между приложением и СУБД, словарь данных/метаданные), история (Кодд → IBM Research → System R → Chamberlin/Boyce → SEQUEL → SQL), стандартизация SQL-86...SQL:2023, почему SQL не совсем "обычный" язык программирования (декларативный, роль оптимизатора запросов), базовые понятия (таблица/поле/запись/столбец/NULL), все ограничения (NOT NULL/DEFAULT/UNIQUE/PRIMARY KEY/FOREIGN KEY/CHECK/INDEX) с проверкой каждого на реальной ошибке, DDL подробно (CREATE TABLE/ALTER TABLE/CREATE INDEX/DROP INDEX/RENAME/DROP TABLE/TRUNCATE TABLE), DML подробно (INSERT/UPDATE/DELETE/SELECT с порядком выполнения FROM→WHERE→GROUP BY→HAVING→SELECT→DISTINCT→ORDER BY→LIMIT/GROUP BY/HAVING/BETWEEN/LIKE/IN/MERGE), агрегатные/строковые/числовые функции, целостность данных (декларативная/процедурная, триггеры, транзакции COMMIT/ROLLBACK) - весь код реально выполнен в PostgreSQL 18.3 во временной базе (удалена после проверки), кто использует SQL по профессиям, рейтинги DBMS/разработчиков со слайдов - поданы как сторонние данные, не перепроверялись.
