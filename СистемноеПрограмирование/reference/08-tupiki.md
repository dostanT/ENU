Справочник. Глава 8. Тупики

Функций Win32 новых нет (пример использует события из главы 6, ExitThread из главы 3). Только логика.

Определение

- Поток в тупике (deadlock), если ждёт событие, которое никогда не произойдёт: либо нет потока, который его вызовет, либо такой поток сам в тупике.
- Хоть один поток процесса в тупике = весь процесс в тупике. Хоть один процесс в тупике = система в тупике.
- Классика: два потока и две критические секции в противоположном порядке. thread_1: Enter(cs1), Enter(cs2); thread_2: Enter(cs2), Enter(cs1). Если thread_1 взял cs1, а thread_2 cs2 - оба ждут друг друга вечно. Правило: захватывать несколько ресурсов ВСЕГДА в одном и том же порядке во всех потоках.

Классификация ресурсов (признак тупика зависит от вида)

- по числу потоков одновременно: совместные (файл на чтение) / монопольные (только один поток; например квант процессора)
- по возможности отобрать: перераспределяемые (preemptable; страница памяти, можно забрать) / неперераспределяемые (принтер)
- по времени жизни: повторно используемые (после освобождения снова доступны; файл, память) / потребляемые (исчезают после использования; сообщение; только логические)
- Повторно используемые: число единиц постоянно, всегда монопольные, всегда неперераспределяемые.
- Потребляемые: число единиц меняется, любые остальные свойства (совместные, перераспределяемые - возможны; пример: квант, если поток прерван более приоритетным, остаток достаётся другому).

Обнаружение

- Граф распределения ресурсов: вершины - потоки. Дуга: повторно используемый ресурс R - от T1 (владеет) к T2 (ждёт); потребляемый - от T1 (произвёл) к T2 (использует). Направление = по ожиданию/потоку данных.
- Теорема 1 (только повторно используемые ресурсы): тупик <=> в графе есть ЦИКЛ.
- Узел: подграф H, где (1) через каждую вершину H проходит цикл, (2) любая дуга между вершиной снаружи и внутри H начинается внутри H (то есть внутрь ничего не втекает).
- Теорема 2 (только потребляемые ресурсы): тупик <=> в графе есть УЗЕЛ. Цикл с дугой снаружи внутрь - ещё не тупик (внешний поток может произвести нужное).

Восстановление

- Прекращение работы (termination): остановить заблокированные потоки. Просто, но может нарушить целостность данных; годится, если потоки работают только с локальными данными.
- Перераспределение (preemption): отнять ресурс у одного заблокированного и отдать другому. Лучший концептуально, но только для перераспределяемых ресурсов.
- Откат на контрольную точку (rollback), чаще всего: в программе расставлены контрольные точки (сохраняется контекст); изменение контекста между двумя точками = транзакция (зафиксирована или отменена). Откат: контекст возвращается на точку, ресурсы, захваченные после неё, освобождаются. Зафиксированную транзакцию откатить нельзя. Кого откатывать: например того, кто захватил меньше всего ресурсов после последней точки.

Предотвращение (три стратегии)

1. Захватить сразу ВСЕ ресурсы и потом работать. Тупика нет. Минусы: ресурсы простаивают, не всегда заранее известен список.
2. При отказе на новый ресурс освободить ВСЕ уже захваченные. Тупика нет. Эффективнее 1, но дорогие откаты/рестарты и возможны ложные срабатывания.
3. Линейно упорядочить типы ресурсов; захватывать только с типом СТРОГО больше уже захваченных. Обычно без потерь эффективности, но годится только если потребности известны до запуска (в системном программировании чаще динамические).
- Общей лучшей стратегии нет; на практике смесь всех трёх, поэтому тупики остаются возможны.

Безопасное завершение потоков в Windows (раздел 8.6, листинг 8.1)

- Идея: поток marker заполняет массив a[size] единицами по случайному индексу i = abs(rand()) % size. Наткнулся на занятый элемент - "тупик": SetEvent(hDeadlock), затем WaitForMultipleObjects(2, hAnswer, FALSE, INFINITE) - ждёт ответ main.
- main: WaitForSingleObject(hDeadlock, INFINITE); печатает массив; спрашивает 'y'. 'y' - SetEvent(hAnswer[0]) (продолжить), иначе SetEvent(hAnswer[1]) (завершиться) и выход из цикла.
- Индекс сработавшего ответа = возврат WaitForMultipleObjects - WAIT_OBJECT_0: 0 -> continue; 1 -> ExitThread(1) (штатно, корректно); другое -> ExitThread(2). WAIT_FAILED - вывести ошибку и вернуть GetLastError().
- Все три события созданы с автосбросом: CreateEvent(NULL, FALSE, FALSE, NULL).
- В конце main: WaitForSingleObject(hMarker, INFINITE); CloseHandle(hMarker).
- ExitThread (поток сам, корректно) против TerminateThread (снаружи, ресурсы не освобождаются).
- Проверка "!a[i]" без защиты допустима только потому, что активен один поток marker; при нескольких нужен InterlockedCompareExchange (глава 7).
