Справочник. Глава 14. Передача данных

Логика

- Между процессами общих переменных нет (разные адресные пространства), поэтому данные идут через канал передачи данных, которым владеет ОС. Внутри одного процесса хватает глобальных переменных + синхронизации (главы 5-8).
- Схема канала (рис. 14.1): T1 -> B1 -> K1 -> M -> K2 -> B2 -> T2.
  - T1, T2 - пользовательские потоки (отправитель, адресат/получатель)
  - B1, B2 - буферы (память); T1 пишет в B1 и T2 читает из B2 только функциями ядра
  - K1, K2 - потоки ядра ОС: K1 переносит B1 -> M, K2 переносит M -> B2
  - M - общая память, доступная только потокам ядра
  - канал (пунктирная рамка на рисунке) = B1, K1, M, K2, B2
- По сети схема та же: M = передающая среда.
- Простейший программный канал: потоки ядра и M заменяются общим ФАЙЛОМ. Windows может проецировать (отображать) файл на адресное пространство процесса (глава 30).
- Способ передачи:
  - потоком - непрерывная последовательность байтов; M может отсутствовать (K1 сразу B1 -> B2); предполагается всегда СИНХРОННОЙ (между отправителем и адресатом непосредственная связь)
  - сообщением - группами байтов, группа = сообщение
- Слово "поток" двойное: "передача потоком" = поток байтов; "потоки ядра/пользовательские" = threads. Слово "буфер" тоже двойное: в 14.1 - кусок памяти (B1, B2), в 14.5 - вместимость связи.

Связи

- Направление (определения книги):
  - полудуплексная - данные только в ОДНОМ направлении
  - дуплексная - в обоих
  - (в сетевой терминологии полудуплекс = "в обе стороны, но по очереди"; на экзамене - определение книги)
- Топология (рассматриваются только полудуплексные связи):
  - 1 -> 1 - связаны два процесса
  - 1 -> N - один связан с N
  - N -> 1 - каждый из N связан с одним
  - N -> M - каждый из N связан с каждым из M
  - терминологию каналов системы задают по-разному; один канал часто поддерживает несколько топологий
- Порядок проектирования: выбрать топологию и направления -> реализовать функциями ОС для установки связи. Система передачи данных - обычно часть ядра ОС.

Сообщения и адресация

- Две операции: send (послать), receive (получить).
- Сообщение = заголовок + тело.
  - заголовок: тип сообщения, имя адресата, имя отправителя, длина (контрольная информация)
  - тело: само сообщение
- Прямая адресация: указываются процессы.
  - send(Process P, сообщение); receive(Process Q, сообщение)
- Косвенная адресация: указывается имя связи.
  - send(Connection S, сообщение); receive(Connection R, сообщение)
- Симметричная адресация - только прямая или только косвенная. Асимметричная - и та, и другая.
- Асимметричная = клиент-сервер: клиенты знают адрес сервера - send(Process Сервер, сообщение); сервер "слушает" связь - receive(Connection S, сообщение), часто называется listen.
- Протокол - набор правил установки связей и передачи данных: набор функций + порядок их вызова (нельзя передавать, не установив связь).

Синхронность

- Отправление синхронное: send блокирует отправителя, пока сообщение не получено адресатом. Иначе асинхронное.
- Получение синхронное: receive блокирует адресата, пока сообщение не придёт. Иначе асинхронное.
- Обмен синхронный только если и отправление, и получение синхронные. Иначе асинхронный.
- Рандеву (rendezvous, "встреча") - синхронный обмен при ПРЯМОЙ адресации; язык Ада.
- Синхронный обмен можно использовать для синхронизации процессов. В Windows синхронизация процессов на РАЗНЫХ компьютерах в локальной сети возможна только через синхронный обмен данными.

Буферизация

- Буфер = вместимость связи = сколько сообщений могут одновременно пересылаться.
- Три типа:
  - нулевая (нет буфера) - возможен ТОЛЬКО синхронный обмен
  - ограниченная - при полном буфере отправитель ждёт освобождения хотя бы одного сообщения
  - неограниченная - отправитель никогда не ждёт
- Тип буферизации связан с синхронностью - учитывать при проектировании.

Карточка для любого канала (глав 15-17)

имя есть/нет; направление; поток или сообщения; синхронный или асинхронный; буферизация; топологии; один компьютер или сеть; адресация (прямая/косвенная/асимметричная).

Функций Win32 в главе нет - чистая теория.
