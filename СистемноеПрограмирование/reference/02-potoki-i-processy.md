Справочник. Глава 2. Потоки и процессы (теория)

Функций Win32 в главе нет - только понятия. Ответы на вопросы "что такое / чем отличается / почему".

Поток

- Поток (thread) = конкретный пройденный процессором маршрут по программе, от первой до последней выполненной инструкции. Один текст программы даёт разные потоки при разных входных данных.
- Вызов функции с ожиданием результата = один поток. Вызов без ожидания = два независимых параллельных потока (порядок завершения не гарантирован).

Контекст потока (память, которую поток видит) и безопасность

- Локальные переменные: у каждого вызова своя копия - параллельный вызов безопасен.
- Глобальные и static-внутри-функции: одна на всех - параллельный вызов даёт гонку данных (race condition).
- Реентерабельная функция: не использует изменяемые глобальные переменные, не использует static внутри функции, не возвращает указатель на static-данные. Ей нечего защищать - безопасна без блокировок.
- Потокобезопасная (thread-safe): трогает общую память, но блокирует доступ (критическая секция, мьютекс, семафор - главы 6-7).
- Нереентерабельная и без блокировки = небезопасна (гонка данных). Реентерабельность и потокобезопасность - не одно и то же.
- Реентерабельность кода микропроцессора: программа не меняет свой код при исполнении.

Состояния потока

- Пара: процессор выделен / не выделен + программа готова / не готова. Невозможно: процессор выделен, программа не готова. Остаётся 3 состояния: блокирован, готов, выполняется.
- Плюс "новый" и "завершён" = 5 состояний.
- Переходы: Create (новый -> готов), Run (готов -> выполняется, даёт ОС), Interrupt (выполняется -> готов, ОС забирает процессор: квант кончился), Block (выполняется -> блокирован, поток сам ждёт событие), Unblock (блокирован -> готов, событие наступило), Exit (выполняется -> завершён).
- Suspend/Resume: один поток приостанавливает/возобновляет ДРУГОЙ, в любом его состоянии. Добавляют "подвешен и готов", "подвешен и блокирован" = 7 состояний.
- Sleep/Wakeup: поток сам засыпает на интервал, ОС будит. Плюс "спит" и "подвешен и спит" = 9 состояний.
- Suspend это не Block: Suspend делает кто-то другой, Block поток делает сам.

Диспетчеризация и планирование

- Однопрограммная система: один поток, при ожидании ввода-вывода процессор простаивает.
- Мультипрограммная: время процессора делится на кванты; по концу кванта поток прерывается.
- При переключении менеджер потоков: сохраняет контекст (регистры) прерываемого, восстанавливает контекст запускаемого, передаёт ему управление.
- Равные приоритеты: одна очередь FIFO (FCFS), прерванный встаёт в конец (циклическое обслуживание).
- Разные приоритеты: по очереди на каждый приоритет; сначала полностью обслуживается высший.
- Планирование = в какую очередь поставить поток. Диспетчеризация = в каком порядке обслуживать очереди.
- Цели алгоритма: загрузка процессора, пропускная способность, минимум времени в системе, минимум ожидания в очереди, минимум времени реакции.
- Квант: слишком мал - много накладных расходов на переключение; слишком велик - долго ждут интерактивные потоки.

Процесс

- Процесс = запущенное приложение + ресурсы (контекст процесса). Обязательно: адресное пространство + потоки в нём.
- Адресные пространства разных процессов не пересекаются - процесс не лезет в память другого (надёжность).
- Потоки одного процесса живут в одном адресном пространстве - общаются через общие переменные (дёшево). Процессы обмениваются данными только через ОС (дорого). Поэтому и появился поток.
- Процесс - контейнер, поток - путь выполнения внутри. У процесса минимум один поток.
