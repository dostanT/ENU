Справочник. Глава 5. Синхронизация (теория)

Функций Win32 в главе нет. Это база, из которой выводятся объекты главы 6.

Две задачи

- Условная синхронизация: поток Б ждёт, пока поток А что-то подготовит (событие).
- Взаимное исключение: в опасном участке кода (критическая секция) одновременно только один поток. Пример проблемы: два потока читают старое значение счётчика, оба прибавляют 1, оба пишут - одно прибавление потеряно.

Определения

- Действие - изменение контекста потока. Непрерывное (атомарное) действие: не прерывается и его контекст меняет только оно само. Одна команда процессора = атомарная команда.
- Однопроцессорная машина: непрерывность = запретить прерывания. Многопроцессорная: этого мало (другой процессор меняет тот же контекст) - нужны аппаратные команды.
- await(условие) действие; - ждёт истинности условия и сразу, непрерывно, выполняет действие.
- await(условие); (без действия) = условная синхронизация, условие = событие (event).
- await(TRUE) действие; = взаимное исключение, действие = критическая секция.
- Событие и критическая секция - два края одного await.

Программное решение (одноконтурное, один процессор)

Событие: bool event = false; поток 1: while (!event); поток 2: event = true;
Минус: активное ожидание (busy waiting) - поток крутится в цикле и жжёт CPU.

Требования к решению взаимного исключения
- безопасность: в критической секции не больше одного потока
- поступательность: потоки не блокируют друг друга бесконечно
- справедливость: каждый попадёт внутрь за ограниченное время

Алгоритм Петерсона (1981), два потока
- флаги x1, x2 = "хочу войти"; q = чья очередь
- вход потока 1: x1 = true; q = 2 (уступаю); while (x2 && q == 2); критическая секция; x1 = false;
- вход потока 2 симметрично (x2 = true; q = 1; while (x1 && q == 1);)
- идея: сначала уступи очередь, потом жди только если соперник хочет войти и сейчас его очередь
- работает только на одном процессоре

Аппаратная реализация (много процессоров): команда блокирует шину памяти на время выполнения
- test-and-set (tas, Motorola 68000): атомарно читает старое значение, ставит 1, возвращает старое. Замок: while (tas(lock)); - выходим, когда вернулся 0
- exchange (xchg, Intel x86): атомарно меняет содержимое двух переменных. Свой ключ = 1, менять с lock, пока в ключе не станет 0
- Оба = спин-блокировка (spinlock, активное ожидание). Работают для любого числа потоков. Минус общий: впустую тратится процессорное время. Отсюда название: алгоритмы активного ожидания (busy waiting).

Примитивы синхронизации (без активного ожидания)

- Примитив = объект ядра ОС; у него очередь заблокированных потоков (ThreadQueue: EnqueueThread приостанавливает через SuspendThread, DequeueThread возобновляет через ResumeThread). Ждущий поток реально блокируется, CPU свободен.
- Condition (условие) - бинарный примитив (флаг event + очередь). Signal(): если кто-то ждёт - разбудить его, иначе event = true (запомнить). Wait(): если event - сбросить его и не блокироваться, иначе встать в очередь и заблокироваться. Реализуется с запретом прерываний внутри.
- Условная синхронизация: Wait в ждущем потоке, Signal в сигналящем.
- Взаимное исключение: Condition создаётся истинным (event = true); вход - Wait, выход - Signal.
- Семафор - обобщение: вместо флага счётчик. Signal увеличивает счётчик (или будит одного из очереди). Wait уменьшает, если > 0, иначе блокирует. Бинарный (0/1) = Condition. Считающий (любое неотрицательное) = подсчёт единиц ресурса: производитель увеличивает, потребитель уменьшает.
- Сильный примитив: очередь строго FIFO. Слабый: иначе (например, по приоритетам). Если в документации не написано про FIFO - на порядок не полагаться.
