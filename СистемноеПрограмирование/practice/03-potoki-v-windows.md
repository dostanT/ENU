Определение потока и модель состояний Windows

1. Перечисли все шесть состояний потока в модели Windows 2000 (готов/выбран/выполняется/ждёт/ждёт ресурс/завершён) и опиши, каким событием поток попадает из "ждёт" именно в "ждёт ресурс", а не сразу обратно в "готов".

Создание потоков

2. Тебе нужно создать поток, которому нужно передать указатель на структуру с двумя полями (int count, char* label). Напиши правильную сигнатуру функции потока для этого случая и объясни, почему у функции потока в Win32 API может быть только один параметр, а не два отдельных.

3. Вызван CreateThread с dwStackSize = 100 (байт). Сколько реально байт получит стек нового потока, и почему именно столько, а не 100?

4. В чём разница между CreateThread и _beginthreadex, и в каком случае книга (со ссылкой на Рихтера) рекомендует использовать именно вторую? Что будет, если поток, созданный через _beginthreadex, завершить через обычный ExitThread, а не _endthreadex?

Завершение потоков

5. Поток завис в бесконечном цикле и не реагирует ни на что. У другого потока есть его HANDLE. Как остановить зависший поток? Какую цену придётся заплатить с точки зрения DLL, загруженных в процессе, по сравнению со штатным завершением через return/ExitThread?

6. Дан код:
```c
volatile UINT count;

void thread()
{
    for (;;)
    {
        ++count;
        Sleep(100);
    }
}
```
Убери мысленно volatile из объявления count. Опиши конкретный сценарий (с двумя параллельными потоками, вызывающими thread()), при котором компилятор может "сломать" правильность программы именно из-за отсутствия volatile.

Приостановка и возобновление потоков

8. Чем Sleep(0) отличается от Sleep(INFINITE)? А чем Sleep вообще принципиально отличается от SuspendThread - кто инициирует остановку в каждом случае?
