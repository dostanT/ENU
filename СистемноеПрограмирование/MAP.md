lectures

01-os-i-win32-api.md - конспект главы 1, "Операционные системы и их интерфейсы" (разделы 1.1-1.5). Зачем нужна ОС и как её классифицируют, что такое Win32 API и на какие категории он делится (курс касается только Base Services и Windows NT Access Control, отсюда все примеры в книге консольные), система типов данных Win32 API (typedef-псевдонимы, смысл приставок P/LP/C), и главное - механизм объектов и дескрипторов (объект как ресурс, HANDLE как "номерок", CreateObject/CloseHandle, подсчёт ссылок на объект).

02-potoki-i-processy.md - конспект главы 2, "Потоки и процессы" (разделы 2.1-2.5). Общая теория без привязки к Windows: что такое поток и чем отличается от процесса, контекст потока и разница между реентерабельностью и потокобезопасностью (на примерах функций с локальной/глобальной/статической переменной), модели состояний потока (3, 5, 7, 9 состояний и операции Create/Exit/Run/Block/Suspend/Sleep и т.д.), диспетчеризация и планирование (кванты времени, FCFS, очереди по приоритету), определение процесса через адресное пространство и владение потоками.

03-potoki-v-windows.md - конспект главы 3, "Потоки в Windows" (разделы 3.1-3.6). То же самое, что глава 2, но уже конкретно Win32 API: определение потока и модель состояний Windows 2000 (готов/выбран/выполняется/ждёт/ждёт ресурс/завершён), создание потоков через CreateThread и почему Рихтер рекомендует _beginthreadex вместо неё, завершение через ExitThread/_endthreadex и опасности TerminateThread, зачем нужен volatile для переменных общих для потоков, приостановка/возобновление через SuspendThread/ResumeThread (это счётчик, а не флаг) и Sleep, псевдодескрипторы через GetCurrentThread, обработка ошибок через GetLastError/FormatMessage и вывод русских сообщений об ошибке на консоль через CharToOem (готовая функция CoutErrorMessage). Ни один Win32-пример не скомпилирован (нет Windows) - объяснено по документации и логике API.

04-processy-v-windows.md - конспект главы 4, "Процессы в Windows" (разделы 4.1-4.8). Процесс как объект ядра и его ресурсы; создание процесса через CreateProcess (родитель/потомок, поиск exe, STARTUPINFO/PROCESS_INFORMATION); завершение через ExitProcess и TerminateProcess и разница между ними; наследование дескрипторов (три обязательных условия, что не наследуется, SetHandleInformation только для Windows 2000); дублирование дескрипторов через DuplicateHandle с изменением прав доступа; псевдодескрипторы (GetCurrentProcess); приоритеты процессов и потоков (шесть классов процесса, семь уровней потока, итоговый базовый приоритет) и динамическое повышение приоритета потоков (SetProcessPriorityBoost/SetThreadPriorityBoost и ловушка с направлением флага DisablePriorityBoost). Четыре Win32-примера: 1) CreateProcess (запуск Notepad и ожидание завершения); 2) наследование дескрипторов - родитель+потомок (два exe) пишут в один файл через унаследованный дескриптор, показаны все 3 обязательных условия; 3) DuplicateHandle - дубликат дескриптора потока только с правом THREAD_TERMINATE, без права на SuspendThread; 4) приоритеты - GetCurrentProcess/GetCurrentThread + SetPriorityClass/SetThreadPriority + ловушка SetProcessPriorityBoost. Ни один Win32-пример не скомпилирован (нет Windows) - каждый объяснён по документации и логике API.

05-sinhronizaciya.md - конспект главы 5, "Синхронизация" (5.1-5.5, теория без Win32). Действие/непрерывное действие, оператор await(условие) действие как общее определение синхронизации, и его два частных случая - событие (await без действия) и критическая секция/взаимное исключение (await(TRUE) действие) - это и есть тот стержень, который объясняет, откуда в главе 6 взялись именно эти четыре Win32-механизма. Наивное решение условной синхронизации через while(!event) и его цена (активное ожидание). Задача взаимного исключения (3 требования - безопасность/поступательность/справедливость) и алгоритм Петерсона (механизм на пальцах, без полного формального доказательства из книги). Аппаратная синхронизация для мультипроцессорных систем (test-and-set, exchange, спин-блокировка). Примитивы синхронизации Condition и Semaphore (с очередью заблокированных потоков вместо активного ожидания) - бинарный/считающий семафор, сильный/слабый (FIFO или нет).

06-sinhronizaciya-potokov-v-windows.md - конспект главы 6, "Синхронизация потоков в Windows" (6.1-6.5), дополнен слайдами преподавателя (SystProg Lec 3th week.pptx). Все 4 Win32-механизма синхронизации из книги, явно увязаны с примитивами главы 5: критическая секция (не объект ядра, быстрее всего, только внутри процесса, владелец - поток, рекурсивный вход) и мьютекс (объект ядра, работает между процессами, abandoned-мьютекс, мнемоника "касса с одним покупателем") - два разных способа взаимного исключения; объекты синхронизации и функции ожидания; события manual-reset/auto-reset (аналогия со стартовым выстрелом и с одним билетом); семафоры (аналогия с платной парковкой на N мест + мнемоника "охранник в бар, первые пять", пример производитель/потребитель из книги). Плюс от преподавателя: пятый механизм - атомарные операции (InterlockedIncrement, гонка данных на counter++, объяснено по документации API); короткий обзорный раздел "другие примитивы" (барьер, read-write lock, future/promise, переменная условия); в частых путаницах добавлено правило "не держи длинные операции внутри критической секции". Пункт "DEADLOCKS" был в содержании презентации преподавателя, но реального контента по нему в слайдах нет - не разобран, это отдельно глава 8 книги на будущее. К основному примеру критической секции добавлено объяснение по логике API, что выведется с защитой (гарантирована целостность каждой строки) и без неё (числа из разных потоков могут перемешаться внутри одной строки) - не проверено запуском. В конце - практическое правило "как выбрать нужный механизм" (расширено атомарными операциями), напрямую увязанное с выбором Critical Section + Event в lab-solutions/labka 3.md.

07-vzaimoiskluchayushiy-dostup-k-peremennym.md - конспект главы 7, "Взаимоисключающий доступ к переменным" (разделы 7.1-7.5, стр. 143-152). Атомарные (блокирующие) функции Windows как лёгкая альтернатива критической секции/мьютексу для простых операций над одной переменной: InterlockedExchange (заменить значение, вернуть старое), InterlockedCompareExchange (заменить только при условии, вернуть старое - и по нему видно, сработала ли замена), InterlockedIncrement/InterlockedDecrement (+-1, вернуть НОВОЕ значение - в отличие от остальных функций главы), InterlockedExchangeAdd (прибавить произвольное число, вернуть старое). Сквозной пример книги - producer/consumer с общим "контейнером" (переменная n), один и тот же сценарий показан 4 раза (по листингу на каждую функцию). Требование выравнивания адреса на границу слова - на практике удовлетворяется само собой для long/LONG/DWORD. Отмечена связь с пятым механизмом синхронизации из lectures/06 (там - по слайдам преподавателя, здесь - по книге полностью) и с TerminateThread из lectures/03 (все примеры главы останавливают потоки через TerminateThread ради простоты демонстрации, это не образец для подражания - раздел 8.6 показывает правильный способ). Ни один пример не скомпилирован (нет Windows) - объяснено по документации и логике API.

08-tupiki.md - конспект главы 8, "Тупики" (разделы 8.1-8.6, стр. 153-164). Определение тупика (поток ждёт событие, которое никогда не произойдёт) и пример с двумя критическими секциями, захватываемыми в разном порядке в двух потоках - классический паттерн взаимного ожидания. Классификация ресурсов по трём осям (совместно используемые/монопольные, перераспределяемые/неперераспределяемые, повторно используемые/потребляемые) - от неё зависит, какой критерий тупика применим. Граф распределения ресурсов, теорема 1 (цикл в графе <=> тупик, для повторно используемых ресурсов) и теорема 2 (узел в графе <=> тупик, для потребляемых ресурсов - узел строже цикла: ничего не должно "втекать" в него снаружи), обе идеи доказательств разобраны своими словами. Три подхода к восстановлению заблокированного процесса (прекращение работы, перераспределение ресурсов, откат на контрольную точку - с разбором плюсов/минусов каждого) и три стратегии предотвращения тупиков (захват всех ресурсов сразу, освобождение всех при отказе, линейное упорядочивание типов ресурсов - у каждой свои недостатки, реальные системы используют смесь). В конце - практический пример 8.6 (листинг 8.1): потоки main/marker, безопасное завершение потока через события (hDeadlock/hAnswer) и ExitThread вместо TerminateThread - явный контраст с главой 7, плюс отдельное замечание книги про InterlockedCompareExchange (глава 7), если бы marker-потоков было несколько. Ни один пример не скомпилирован (нет Windows) - объяснено по документации и логике API.

Все 12 листингов книги (13.1-13.12) разобраны под своими разделами. Ни один пример не скомпилирован (нет Windows) - объяснено по документации и логике API.

15-anonimnye-kanaly.md - конспект главы 15, "Работа с анонимными каналами в Windows" (15.1-15.6, стр. 243-264).
