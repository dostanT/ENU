Глава 17. Работа с почтовыми ящиками в Windows

Суть

Почтовый ящик (mailslot) - это односторонний "ящик для писем" внутри операционной системы. Сервер вешает ящик у себя (создаёт его), а клиенты бросают в него сообщения; читает письма только хозяин ящика. Ответа в ту же сторону нет, подтверждения "письмо дошло" тоже нет. Зато ящик умеет то, чего не умеют каналы: если в локальной сети несколько серверов создали ящики с ОДНИМ именем, короткое письмо клиента получат ВСЕ - как рассылка.

Это последняя глава части IV (обмен данными между процессами): анонимный канал (глава 15) - "труба между родственниками", именованный канал (глава 16) - "телефонная линия с номером для разговора туда и обратно", почтовый ящик (эта глава) - "почтовый ящик: бросил письмо и ушёл". Как и каналы, ящик открывается и используется как обычный файл: клиент - CreateFile + WriteFile, сервер - ReadFile.

17.1 Концепция почтовых ящиков

Определение книги: почтовым ящиком называется объект ядра операционной системы, который обеспечивает передачу сообщений от процессов-клиентов к процессам-серверам, выполняющимся на компьютерах в пределах локальной сети. Процесс, который создаёт ящик, - сервер почтового ящика. Процессы, которые связываются с именованным ящиком, - клиенты.

Характеристики (ответ на "карточку" из главы 14):

- имеют имя, по которому клиенты связываются с ящиком;
- направление передачи данных - от клиента к серверу (только в одну сторону);
- передача данных - сообщениями;
- обмен данными может быть и синхронным, и асинхронным.

Про синхронность (моё сопоставление с определениями из раздела 14.4, книга здесь сама этого не расписывает): доставка сообщения от клиента серверу системой не подтверждается, то есть клиент не ждёт, пока сервер получит письмо, - отправление по сути асинхронное. А на стороне сервера всё зависит от времени ожидания чтения (dwReadTimeout, раздел 17.2): 0 - ReadFile сразу возвращается, если писем нет (асинхронное получение), бесконечное ожидание - ReadFile ждёт письма (синхронное получение).

Про несколько серверов у одного ящика. Хотя данные идут только от клиента к серверу, у одного ящика может быть НЕСКОЛЬКО серверов. Так получается, когда несколько серверов создают ящики с одинаковыми именами. Тогда все сообщения, которые клиент посылает в такой ящик, получат ВСЕ серверы этого ящика. Но только при условии, что длина сообщения меньше 425 байт - потому что в этом случае сообщения передаются дейтаграммами. Выходит, что почтовые ящики обеспечивают ОДНОНАПРАВЛЕННУЮ связь типа "многие-ко-многим" (по классификации из главы 14 - топология N -> M, но только в одну сторону). Доставка сообщения от клиента к серверам системой не подтверждается. Отдельное замечание книги: семейство Windows NT не поддерживает передачу сообщений длиной 425 и 426 байт.

Как передаются сообщения - две ветки.

Первая: короткое сообщение (меньше 425 байт). Оно передаётся как дейтаграмма. Дейтаграмма - это небольшой пакет с передаваемым по сети сообщением, в который вложена ещё и информация об отправителе и получателе. Картинка из жизни: открытка. Дейтаграмма рассылается ВСЕМ серверам с этим именем ящика. Пакет маленький, поэтому дейтаграммы рассылаются быстро, но гарантии доставки нет: в дейтаграмме не хранится информация, которая позволила бы контролировать доставку.

Вторая: длинное сообщение (больше 426 байт). Оно может передаваться только от ОДНОГО клиента к ОДНОМУ серверу и использует для этого протокол SMB (Server Message Block) - протокол передачи данных по сети. Картинка из жизни: заказное письмо одному адресату. Длина сообщения, передаваемого в ящик, не может превышать 64 Кбайт. Опять же: при SMB сообщения идут только от одного клиента к одному серверу ящика.

Ещё одно важное замечание: почтовые ящики можно рассматривать как ПСЕВДОФАЙЛЫ, расположенные в оперативной памяти компьютера. Поэтому для доступа к ним используются те же функции, что и для доступа к обычным файлам (подробно - глава 24).

Порядок работы с почтовыми ящиками:

1. создание почтового ящика сервером;
2. соединение клиента с почтовым ящиком;
3. обмен данными через почтовый ящик;
4. закрытие почтового ящика клиентом и сервером.

Сравни с именованным каналом (глава 16): там сервер ждал клиента (ConnectNamedPipe) и разрывал связь (DisconnectNamedPipe), а клиент искал свободный экземпляр (WaitNamedPipe). У ящика ничего этого нет: сервер просто создал ящик, клиент просто открыл его и бросил письмо. Никакой "установки связи" между двумя конкретными процессами не происходит.

Карточка почтового ящика (по образцу главы 14): имя - есть; направление - только от клиента к серверу; передача - сообщениями; обмен - и синхронный, и асинхронный (см. выше); топологии - однонаправленная N -> M для коротких сообщений (меньше 425 байт, дейтаграммы), 1 -> 1 для длинных (SMB); компьютеры - локальная сеть; адресация - по имени ящика, а не процесса (по определениям главы 14 это косвенная адресация).

17.2 Создание почтовых ящиков

Почтовые ящики создаются процессом-сервером функцией CreateMailslot:

```
HANDLE CreateMailslot(
    LPCTSTR lpName,                            // имя почтового ящика
    DWORD   dwMaxMessageSize,                  // максимальная длина сообщения
    DWORD   dwReadTimeout,                     // интервал ожидания
    LPSECURITY_ATTRIBUTES lpSecurityAttributes // атрибуты безопасности
);
```

(В прототипе книги после dwMaxMessageSize пропущена запятая - опечатка вёрстки.) При успехе возвращает дескриптор почтового ящика, при неудаче - INVALID_HANDLE_VALUE. Пример из жизни: вешаешь у подъезда почтовый ящик. Нужно решить: какая надпись на ящике (имя), письма какой максимальной длины принимает, как долго ты готов стоять и ждать у ящика, если он пуст, и кому вообще можно бросать письма. Параметры:

lpName - имя ящика. Строка вида:

```
\\.\mailslot\mailslot_name
```

Здесь "." означает локальную машину (новый ящик всегда создаётся на локальной машине), слово mailslot фиксированное, mailslot_name - имя, которое задаёт пользователь; оно нечувствительно к регистру. Напоминает имя канала из главы 16 - только вместо \pipe\ здесь \mailslot\. В коде C косые черты, как всегда, удваиваются: "\\\\.\\mailslot\\demo_mailslot".

dwMaxMessageSize - максимальная длина сообщения в байтах, которое может быть записано в ящик. Значение 0 в примерах означает "длина сообщения произвольна" (так сказано в комментарии листингов).

dwReadTimeout - временной интервал в миллисекундах, в течение которого функция ReadFile ждёт поступления сообщения в ящик. Если 0 - при отсутствии сообщения ReadFile немедленно возвращает управление. Для бесконечного ожидания - значение MAILSLOT_WAIT_FOREVER.

lpSecurityAttributes - атрибуты безопасности; NULL - защита по умолчанию.

Несколько процессов могут создать ящики с одним и тем же именем. Тогда сообщение, посланное клиентом, может быть доставлено не в один ящик, а во ВСЕ такие ящики - при условии, что они работают на компьютерах внутри одного ДОМЕНА (домен - группа компьютеров сети под общим управлением). Режим доставки сообщений зависит от режима открытия ящика клиентом (то есть от того, каким именем клиент открыл ящик - см. 17.3). Пример создания ящика - в разделе 17.4.

17.3 Соединение клиентов с почтовым ящиком

Клиент использует ту же функцию CreateFile, что и с каналом (глава 16, раздел 16.4), и с обычными файлами:

```
HANDLE CreateFile(
    LPCTSTR lpFileName,                         // указатель на имя почтового ящика
    DWORD   dwDesiredAccess,                    // чтение или запись в канал
    DWORD   dwShareMode,                        // режим совместного использования
    LPSECURITY_ATTRIBUTES lpSecurityAttributes, // атрибуты безопасности
    DWORD   dwCreationDisposition,              // флаги открытия почтового ящика
    DWORD   dwFlagsAndAttributes,               // флаги и атрибуты
    HANDLE  hTemplateFile                       // дополнительные атрибуты
);
```

При успехе возвращает дескриптор почтового ящика, при неудаче - INVALID_HANDLE_VALUE. Что передавать, когда CreateFile открывает ящик:

lpFileName - имя ящика. Здесь формат ГЛАВНОЕ, потому что от него зависит, КТО получит сообщение. Четыре формата:

```
почтовый ящик на локальном компьютере:              \\.\mailslot\имя_почтового_ящика
почтовый ящик на компьютере с указанным именем:     \\имя_компьютера\mailslot\имя_почтового_ящика
почтовый ящик в домене с указанным именем:          \\имя_домена\mailslot\имя_почтового_ящика
почтовый ящик в первичном домене системы:           \\*\mailslot\имя_почтового_ящика
```

Что происходит в каждом случае:

- \\.\mailslot\... - сообщения доставляются только в ящики с заданным именем, расположенные на ЛОКАЛЬНОЙ машине;
- \\имя_компьютера\mailslot\... - только в ящики с заданным именем на компьютере с указанным именем;
- \\имя_домена\mailslot\... - в ящики с заданным именем, созданные внутри домена с указанным именем (вот она - рассылка "всем серверам домена");
- \\*\mailslot\... - в ящики с заданным именем, созданные внутри ПЕРВИЧНОГО домена системы.

Картинка из жизни: адрес на конверте. "Кв. 5, наш дом" - письмо попадёт в один конкретный ящик; "всем жильцам района" - в ящики с этой надписью у всех.

dwDesiredAccess - должно быть GENERIC_WRITE (разрешает запись в ящик). Клиент только пишет - читать чужой ящик нельзя.

dwShareMode - режим совместного использования; любая комбинация FILE_SHARE_READ (разрешает совместное чтение из ящика) и FILE_SHARE_WRITE (разрешает совместную запись в ящик).

lpSecurityAttributes - атрибуты безопасности, пока NULL.

dwCreationDisposition - ВСЕГДА OPEN_EXISTING, потому что клиент всегда открывает существующий ящик.

dwFlagsAndAttributes - 0 (по умолчанию) или FILE_ATTRIBUTE_NORMAL.

hTemplateFile - при работе с ящиками не используется, ставится NULL.

Пример соединения клиента - в следующем разделе.

17.4 Обмен данными через почтовый ящик

Обмен идёт обычными функциями работы с файлами: клиент записывает данные в ящик функцией WriteFile, сервер читает функцией ReadFile (прототипы - в конспекте главы 15, раздел 15.4; подробно про эти функции - глава 24). Сервер в принципе может и записывать сообщения в ящик, но это имеет смысл только когда в домене есть несколько ящиков с одинаковыми именами, созданных разными процессами: тогда одинаковые сообщения получат все.

Пример 1 (листинги 17.1 и 17.2): сервер создаёт ящик на локальной машине, ждёт одно сообщение (целое число), читает его и печатает. Клиент открывает ящик, вводит с клавиатуры число и записывает его в ящик. Запуск: СНАЧАЛА сервер (он создаёт ящик), потом клиент (он открывает уже существующий).

Листинг 17.1 - процесс-сервер почтового ящика:

```c
#include <windows.h>
#include <iostream.h>

int main()
{
    HANDLE hMailslot;       // дескриптор почтового ящика

    // создаем почтовый ящик
    hMailslot = CreateMailslot(
        "\\\\.\\mailslot\\demo_mailslot",   // имя почтового ящика
        0,                        // длина сообщения произвольна
        MAILSLOT_WAIT_FOREVER,    // ждем сообщения произвольно долго
        NULL                      // безопасность по умолчанию
        );
    // проверяем на успешное создание
    if (hMailslot == INVALID_HANDLE_VALUE)
    {
        cerr << "Create mailslot failed." << endl
            << "The last error code: " << GetLastError() << endl;
        cout << "Press any key to finish server.";
        cin.get();

        return 0;
    }

    cout << "The mailslot is created." << endl;

    cout << "The mailslot is waiting a message." << endl;
    // читаем одно целое число из почтового ящика
    int nData;
    DWORD dwBytesRead;
    if (!ReadFile(
            hMailslot,          // дескриптор почтового ящика
            &nData,             // адрес буфера для ввода данных
            sizeof(nData),      // количество читаемых байтов
            &dwBytesRead,       // количество прочитанных байтов
            (LPOVERLAPPED)NULL  // передача данных синхронная
            ))
    {
        cerr << "Read file failed." << endl
            << "The last error code: " << GetLastError() << endl;
        CloseHandle(hMailslot);
        cout << "Press any key to finish server.";
        cin.get();

        return 0;
    }

    // выводим число на консоль
    cout << "The number " << nData << " was read by the server" << endl;

    // закрываем дескриптор почтового ящика
    CloseHandle(hMailslot);

    // завершаем процесс
    cout << "Press any key to exit.";
    cin.get();

    return 0;
}
```

Листинг 17.2 - процесс-клиент почтового ящика. Предполагается, что клиент запускается на той же локальной машине, что и сервер. Иначе в имени ящика нужно указать не точку, а имя компьютера, на котором создан ящик, или имя домена, в котором созданы ящики с одинаковыми именами:

```c
#include <windows.h>
#include <iostream.h>

int main()
{
    HANDLE hMailslot;
    char mailslotName[] = "\\\\.\\mailslot\\demo_mailslot";

    // связываемся с почтовым ящиком
    hMailslot = CreateFile(
        mailslotName,        // имя почтового ящика
        GENERIC_WRITE,       // записываем в ящик
        FILE_SHARE_READ,     // разрешаем одновременное чтение из ящика
        NULL,                // защита по умолчанию
        OPEN_EXISTING,       // открываем существующий канал
        0,                   // атрибуты по умолчанию
        NULL                 // дополнительных атрибутов нет
    );

    // проверяем связь с почтовым ящиком
    if (hMailslot == INVALID_HANDLE_VALUE)
    {
        cerr << "Create file failed." << endl
            << "The last error code: " << GetLastError() << endl;
        cout << "Press any key to finish the client.";
        cin.get();

        return 0;
    }

    // вводим целое число
    int n;
    cout << "Input an integer: ";
    cin >> n;

    // пишем число в почтовый ящик
    DWORD dwBytesWritten;
    if (!WriteFile(
            hMailslot,          // дескриптор почтового ящика
            &n,                 // данные
            sizeof(n),          // размер данных
            &dwBytesWritten,    // количество записанных байтов
            NULL                // синхронная запись
            ))
    {
        // ошибка записи
        cerr << "Write file failed: " << endl
            << "The last error code: " << GetLastError() << endl;
        cout << "Press any key to finish the client.";
        cin.get();

        CloseHandle(hMailslot);
        return 0;
    }

    // закрываем дескриптор канала
    CloseHandle(hMailslot);
    // завершаем процесс
    cout << "The number is written by the client." << endl
        << "Press any key to exit." << endl;
    cin.get();

    return 0;
}
```

Не скомпилировано по-настоящему (нет Windows) - проверено по документации и логике API. Механизм по шагам.

Сервер. CreateMailslot создаёт ящик "\\.\mailslot\demo_mailslot": 0 - длина сообщений произвольна, MAILSLOT_WAIT_FOREVER - ReadFile будет ждать сообщение бесконечно долго, NULL - защита по умолчанию. Если вернулся INVALID_HANDLE_VALUE - печатает код ошибки и выходит. Дальше печатает "The mailslot is created." и "The mailslot is waiting a message." и вызывает ReadFile на четыре байта (sizeof(int)) - вот здесь сервер и замирает, пока в ящике ничего нет (из-за бесконечного ожидания). Как только клиент положил число, ReadFile возвращается, сервер печатает число и закрывает дескриптор. Последний аргумент ReadFile в книге записан как (LPOVERLAPPED)NULL - то же самое, что просто NULL: синхронное чтение.

Клиент. CreateFile открывает ящик на запись (GENERIC_WRITE) - как и требует книга; OPEN_EXISTING и остальные значения - по таблице из 17.3. Имя с точкой - ящик на этом же компьютере. Клиент просит ввести число (cin >> n), записывает его четырьмя байтами и закрывает дескриптор. Клиент ни на что не ждёт: письмо брошено - и всё. Если запустить клиента раньше сервера, CreateFile не найдёт ящика и клиент напечатает "Create file failed." и код ошибки.

Ожидаемое поведение (рассуждение по логике, НЕ проверенный вывод). Сервер: "The mailslot is created." - "The mailslot is waiting a message." - долгая пауза, пока клиент не введёт число - "The number 42 was read by the server" (если ввели 42) - "Press any key to exit.". Клиент: "Input an integer: " (ввод) - "The number is written by the client." - "Press any key to exit.".

В заключение раздела книга отмечает: раз доступ к ящикам не отличается от доступа к файлам, для обмена через них можно использовать и WriteFileEx/ReadFileEx (асинхронные функции, глава 24).

17.5 Получение информации о почтовом ящике

Сервер ящика часто хочет знать: есть ли письма, сколько, и какого размера следующее. Особенно это полезно потому, что письма бывают РАЗНОЙ длины, а ReadFile читает одно письмо - и нужен буфер подходящего размера. Для получения таких сведений служит GetMailslotInfo:

```
BOOL GetMailslotInfo(
    HANDLE  hMailslot,          // дескриптор почтового ящика
    LPDWORD lpMaxMessageSize,   // максимальная длина сообщения
    LPDWORD lpNextSize,         // длина следующего сообщения
    LPDWORD lpMessageCount,     // количество сообщений
    LPDWORD lpReadTimeout       // интервал ожидания сообщения
);
```

(В прототипе книги пропущены запятые после lpMaxMessageSize и lpMessageCount - опечатка вёрстки.) При успехе возвращает ненулевое значение, при неудаче - по тексту книги "NULL" (то есть 0, FALSE). Параметры:

- hMailslot - дескриптор ящика, возвращённый функцией CreateMailslot;
- lpMaxMessageSize - адрес DWORD, куда функция положит максимальную длину сообщения, которое можно записать в ящик. Не нужно - NULL;
- lpNextSize - адрес DWORD, куда функция положит длину СЛЕДУЮЩЕГО сообщения в ящике. Если сообщений нет - функция запишет значение MAILSLOT_NO_MESSAGE. Не нужно - NULL;
- lpMessageCount - адрес DWORD, куда функция положит количество сообщений, лежащих в ящике. Не нужно - NULL;
- lpReadTimeout - адрес DWORD, куда функция положит интервал в миллисекундах, в течение которого ReadFile ждёт, если ящик пуст, пока клиент не запишет сообщение. Не нужно - NULL.

Примеры (листинги 17.3 и 17.4): GetMailslotInfo используется для получения сведений о сообщениях, хранящихся в ящике. Сервер читает сообщения "по мере поступления": узнаёт, сколько их и какого размера следующее, выделяет буфер ровно нужного размера и читает. Клиент посылает несколько сообщений.

Листинг 17.3 - процесс-сервер почтового ящика:

```c
#include <windows.h>
#include <iostream.h>

int main()
{
    HANDLE hMailslot;           // дескриптор почтового ящика
    DWORD dwNextMessageSize;    // размер следующего сообщения
    DWORD dwMessageCount;       // количество сообщений

    // создаем почтовый ящик
    hMailslot = CreateMailslot(
        "\\\\.\\mailslot\\demo_mailslot",   // имя почтового ящика
        0,                        // длина сообщения произвольна
        MAILSLOT_WAIT_FOREVER,    // ждем сообщения произвольно долго
        NULL                      // безопасность по умолчанию
        );
    // проверяем на успешное создание
    if (hMailslot == INVALID_HANDLE_VALUE)
    {
        cerr << "Create mailslot failed." << endl
            << "The last error code: " << GetLastError() << endl;
        cout << "Press any key to finish server.";
        cin.get();

        return 0;
    }

    cout << "The mailslot is created." << endl;

    // ждем сообщений
    cout << "Press any key to read messages." << endl;
    cin.get();

    // получаем информацию о почтовом ящике
    if (!GetMailslotInfo(
            hMailslot,              // дескриптор почтового ящика
            NULL,                   // максимальный размер сообщения не нужен
            &dwNextMessageSize,     // размер следующего сообщения
            &dwMessageCount,        // количество сообщений
            NULL))                  // интервал ожидания не нужен
    {
        cerr << "Get mailslot info failed." << endl
            << "The last error code: " << GetLastError() << endl;
        cout << "Press any key to finish server.";
        cin.get();

        return 0;
    }

    // читаем сообщения
    while (dwMessageCount != 0)
    {
        DWORD dwBytesRead;
        char* pchMessage;

        // захватываем память для сообщения
        pchMessage = (char*) new char[dwNextMessageSize];

        // читаем одно сообщение
        if (!ReadFile(
                hMailslot,              // дескриптор канала
                pchMessage,             // адрес буфера для ввода данных
                dwNextMessageSize,      // количество читаемых байтов
                &dwBytesRead,           // количество прочитанных байтов
                NULL                    // передача данных синхронная
                ))
        {
            cerr << "Read file failed." << endl
                << "The last error code: " << GetLastError() << endl;
            CloseHandle(hMailslot);
            cout << "Press any key to finish server.";
            cin.get();

            return 0;
        }

        // выводим сообщение на консоль
        cout << "The message << " << pchMessage << " >> was read" << endl;

        // получаем информацию о следующем сообщении
        if (!GetMailslotInfo(
                hMailslot,              // дескриптор почтового ящика
                NULL,                   // максимальный размер сообщения не нужен
                &dwNextMessageSize,     // размер следующего сообщения
                &dwMessageCount,        // количество сообщений
                NULL))                  // интервал ожидания не нужен
        {
            cerr << "Get mailslot info failed." << endl
                << "The last error code: " << GetLastError() << endl;
            cout << "Press any key to finish server.";
            cin.get();

            return 0;
        }

        // освобождаем память для сообщения
        delete[] pchMessage;
    }

    // закрываем дескриптор почтового ящика
    CloseHandle(hMailslot);

    // завершаем процесс
    cout << "Press any key to exit.";
    cin.get();

    return 0;
}
```

Листинг 17.4 - процесс-клиент почтового ящика, посылающий несколько сообщений. Как сервер, так и клиент находятся на локальном компьютере:

```c
#include <windows.h>
#include <iostream.h>
#include <string.h>

int main()
{
    HANDLE hMailslot;
    char mailslotName[] = "\\\\.\\mailslot\\demo_mailslot";

    // связываемся с почтовым ящиком
    hMailslot = CreateFile(
        mailslotName,          // имя почтового ящика
        GENERIC_WRITE,         // записываем в ящик
        FILE_SHARE_READ,       // разрешаем одновременное чтение из ящика
        NULL,                  // защита по умолчанию
        OPEN_EXISTING,         // открываем существующий канал
        0,                     // атрибуты по умолчанию
        NULL                   // дополнительных атрибутов нет
        );

    // проверяем связь с почтовым ящиком
    if (hMailslot == INVALID_HANDLE_VALUE)
    {
        cerr << "Create file failed." << endl
            << "The last error code: " << GetLastError() << endl;
        cout << "Press any key to finish the client.";
        cin.get();

        return 0;
    }

    // вводим количество передаваемых сообщений
    int n;
    cout << "Input a number of messages: ";
    cin >> n;
    cin.get();

    // пишем сообщения в почтовый ящик
    for (int i = 0; i < n; ++i)
    {
        DWORD dwBytesWritten;
        char pchMessage[256];
        int nMessageSize;

        cout << "Input message: ";
        // читаем сообщение
        cin.getline(pchMessage, 256);
        // определем длину сообщения
        nMessageSize = strlen(pchMessage) + 1;

        // пишем сообщение
        if (!WriteFile(
                hMailslot,          // дескриптор почтового ящика
                pchMessage,         // данные
                nMessageSize,       // размер данных
                &dwBytesWritten,    // количество записанных байтов
                NULL                // синхронная запись
                ))
        {
            // ошибка записи
            cerr << "Write file failed: " << endl
                << "The last error code: " << GetLastError() << endl;
            cout << "Press any key to finish the client.";
            cin.get();

            CloseHandle(hMailslot);

            return 0;
        }
    }

    // закрываем дескриптор канала
    CloseHandle(hMailslot);
    // завершаем процесс
    cout << "The messages are written by the client." << endl
        << "Press any key to exit." << endl;
    cin.get();

    return 0;
}
```

Не скомпилировано по-настоящему - проверено по документации и логике API. Механизм по шагам.

Идея примера: ящик КОПИТ письма, пока сервер занят чем-то другим. Сервер создаёт ящик и ждёт нажатия клавиши ("Press any key to read messages.") - это как хозяин, который ушёл на работу и вернётся вечером. За это время клиент успевает положить несколько писем. Когда сервер "вернулся" (нажата клавиша), он вызывает GetMailslotInfo и узнаёт две вещи: сколько писем ждёт (dwMessageCount) и какого размера первое (dwNextMessageSize). Дальше цикл "пока письма есть": выделить буфер под ОДНО письмо ровно нужного размера (new char[dwNextMessageSize]) - ReadFile читает одно письмо - напечатать его - снова GetMailslotInfo, чтобы узнать размер следующего и обновить счётчик - освободить буфер (delete[]). Когда счётчик дойдёт до нуля, цикл закончится. Клиент спрашивает, сколько сообщений отправить, затем n раз читает строку с клавиатуры и записывает её в ящик; длина берётся как strlen(...) + 1 (плюс завершающий нулевой символ, чтобы сервер получил корректную строку). cin.get() после cin >> n съедает символ перевода строки, оставшийся в буфере ввода, иначе первый getline вернул бы пустую строку.

Ожидаемое поведение (рассуждение по логике, НЕ проверенный вывод). Сервер сначала: "The mailslot is created." и "Press any key to read messages." - стоит. Клиент: "Input a number of messages: " (например, 3) - три раза "Input message: " (вводятся три строки) - "The messages are written by the client." - "Press any key to exit.". После этого в сервере нажимают клавишу: по строке "The message << ... >> was read" на каждое из трёх сообщений в порядке отправки - "Press any key to exit.". Ловушка порядка (моё наблюдение по коду): если нажать клавишу в сервере ДО того, как клиент что-нибудь записал, GetMailslotInfo вернёт dwMessageCount = 0, цикл не выполнится ни разу, и сервер завершится, ничего не прочитав.

17.6 Изменение времени ожидания сообщения

Время ожидания чтения (dwReadTimeout), заданное в CreateMailslot, можно изменить уже после создания ящика функцией SetMailslotInfo:

```
BOOL SetMailslotInfo(
    HANDLE hMailslot,       // дескриптор почтового ящика
    DWORD  dwReadTimeout    // интервал ожидания сообщения
);
```

При успехе возвращает ненулевое значение, при неудаче - (по тексту книги) NULL. Параметры: hMailslot - дескриптор ящика, полученный вызовом CreateMailslot; dwReadTimeout - новый интервал в миллисекундах, в течение которого ReadFile ждёт поступления сообщения в ящик. Значение 0 - при отсутствии сообщений ReadFile немедленно возвращает управление. Для бесконечного ожидания - MAILSLOT_WAIT_FOREVER.

Листинг 17.5 - программа, в которой SetMailslotInfo устанавливает новый интервал ожидания (сначала интервал равен 0, потом меняется на 3000 миллисекунд):

```c
#include <windows.h>
#include <iostream.h>

int main()
{
    HANDLE hMailslot;           // дескриптор почтового ящика
    DWORD dwReadTimeout;        // интервал для ожидания сообщения

    // создаем почтовый ящик
    hMailslot = CreateMailslot(
        "\\\\.\\mailslot\\demo_mailslot",   // имя почтового ящика
        0,      // длина сообщения произвольна
        0,      // интервал ожидания равен нулю
        NULL    // защита по умолчанию
        );
    // проверяем на успешное создание
    if (hMailslot == INVALID_HANDLE_VALUE)
    {
        cerr << "Create mailslot failed." << endl
            << "The last error code: " << GetLastError() << endl;
        cout << "Press any key to finish server.";
        cin.get();

        return 0;
    }

    cout << "The mailslot is created." << endl;

    // получаем информацию о почтовом ящике
    if (!GetMailslotInfo(
            hMailslot,          // дескриптор почтового ящика
            NULL,               // максимальный размер сообщения не нужен
            NULL,               // размер следующего сообщения не нужен
            NULL,               // количество сообщений не нужно
            &dwReadTimeout))    // интервал ожидания сообщения
    {
        cerr << "Get mailslot info failed." << endl
            << "The last error code: " << GetLastError() << endl;
        cout << "Press any key to finish server.";
        cin.get();

        return 0;
    }

    cout << "Read timeout: " << dwReadTimeout << endl;

    if (!SetMailslotInfo(
            hMailslot,      // дескриптор почтового ящика
            3000))          // изменяем интервал ожидания
    {
        cerr << "Set mailslot info failed." << endl
            << "The last error code: " << GetLastError() << endl;
        cout << "Press any key to finish server.";
        cin.get();

        return 0;
    }

    // получаем информацию о почтовом ящике
    if (!GetMailslotInfo(
            hMailslot,          // дескриптор почтового ящика
            NULL,               // максимальный размер сообщения не нужен
            NULL,               // размер следующего сообщения не нужен
            NULL,               // количество сообщений не нужно
            &dwReadTimeout))    // интервал ожидания сообщения
    {
        cerr << "Get mailslot info failed." << endl
            << "The last error code: " << GetLastError() << endl;
        cout << "Press any key to finish server.";
        cin.get();

        return 0;
    }

    cout << "Read timeout: " << dwReadTimeout << endl;

    // закрываем дескриптор почтового ящика
    CloseHandle(hMailslot);

    // завершаем процесс
    cout << "Press any key to exit.";
    cin.get();

    return 0;
}
```

Не скомпилировано по-настоящему - проверено по документации и логике API. Механизм по шагам: программа создаёт ящик с нулевым временем ожидания, читает его через GetMailslotInfo (нужен только последний параметр, остальные NULL - "не нужно"), печатает, вызывает SetMailslotInfo(hMailslot, 3000), читает ещё раз и печатает. Ожидаемое поведение (рассуждение по логике, НЕ проверенный вывод): "The mailslot is created." - "Read timeout: 0" - "Read timeout: 3000" - "Press any key to exit.". Смысл нового значения: теперь ReadFile на пустом ящике будет ждать сообщение до трёх секунд (а не возвращаться сразу).

Частые путаницы и ошибки

Считают, что ящик двусторонний. Данные идут ТОЛЬКО от клиента к серверу: клиент открывает ящик с GENERIC_WRITE и пишет, сервер читает. Ответить клиенту через тот же ящик нельзя (для двустороннего разговора - именованный канал, глава 16).

Ждут подтверждения доставки. Его нет: система не подтверждает, что сообщение дошло до сервера, а дейтаграммы вообще не содержат данных для контроля доставки. Для надёжной доставки одного сообщения одному серверу нужен канал.

Путают пороги длины. Меньше 425 байт - дейтаграмма: рассылается ВСЕМ серверам с этим именем (в пределах домена), быстро, но без гарантии. Больше 426 байт - SMB, только от одного клиента к одному серверу, не более 64 Кбайт. Сообщения длиной 425 и 426 байт в семействе Windows NT не поддерживаются. Поэтому нельзя надеяться на рассылку "всем" для длинных сообщений.

Путают формат имени у клиента. \\.\mailslot\... - только локальная машина; \\компьютер\mailslot\... - один заданный компьютер; \\домен\mailslot\... - все ящики с этим именем в домене; \\*\mailslot\... - в первичном домене. От формата зависит, КТО получит сообщение (раздел 17.3). Клиент на другом компьютере с точкой в имени ящик на сервере не найдёт.

Путают имя на стороне сервера и клиента. Сервер в CreateMailslot всегда пишет \\.\mailslot\имя - ящик создаётся только на локальной машине. Клиент выбирает один из четырёх форматов.

Забывают dwReadTimeout. Значение 0 - ReadFile на пустом ящике сразу возвращается (а не ждёт); MAILSLOT_WAIT_FOREVER - ждёт бесконечно. Сервер из листинга 17.1 с MAILSLOT_WAIT_FOREVER, пока нет письма, "висит" в ReadFile.

Берут буфер фиксированного размера, не зная длины письма. Письма бывают разной длины, а ReadFile читает одно сообщение. Поэтому в листинге 17.3 перед каждым ReadFile вызывается GetMailslotInfo и буфер выделяется ровно под следующее сообщение. lpNextSize при пустом ящике содержит MAILSLOT_NO_MESSAGE - поэтому цикл в листинге управляется счётчиком сообщений, а не размером.

Запускают клиента раньше сервера. Клиент открывает существующий ящик (OPEN_EXISTING); пока сервер его не создал, CreateFile завершается ошибкой.

Опечатки самой книги в этой главе (чтобы не путаться): в прототипах CreateMailslot и GetMailslotInfo пропущены запятые после dwMaxMessageSize, lpMaxMessageSize и lpMessageCount; в GetMailslotInfo и SetMailslotInfo неудача описана как "NULL" вместо FALSE; в листингах 17.2 и 17.4 комментарий "открываем существующий канал" вместо "ящик"; в листинге 17.4 "определем" вместо "определяем".

Итог: какие функции и для чего

- CreateMailslot - сервер создаёт ящик (имя, максимальная длина сообщения, время ожидания чтения, защита);
- CreateFile - клиент открывает ящик (GENERIC_WRITE, OPEN_EXISTING; формат имени выбирает, кто получит сообщение);
- WriteFile - клиент записывает сообщение (доставка не подтверждается);
- ReadFile - сервер читает ОДНО сообщение (ждёт по dwReadTimeout);
- GetMailslotInfo - сервер узнаёт: максимальную длину сообщения, длину следующего, количество сообщений, время ожидания;
- SetMailslotInfo - сервер меняет время ожидания чтения;
- CloseHandle - закрыть дескриптор ящика.
