Глава 11. Работа с окном консоли

Суть

До сих пор консоль разбиралась как абстрактный набор буферов (входной буфер, буфер экрана). Но у консоли есть ещё и вполне обычное окно на экране - с заголовком, границами, положением. Эта глава - именно про это окно: как получить его дескриптор (и что с этим дескриптором вообще можно сделать), как прочитать и поменять заголовок, и как управлять размером/положением этого окна относительно буфера экрана, который в нём показывается.

11.1 Получение дескриптора окна консоли

Дескриптор окна консоли можно получить функцией GetConsoleWindow:

```
HWND GetConsoleWindow(VOID);
```

При успехе возвращает дескриптор окна консоли, при неудаче - NULL (это значит, что у приложения консоли попросту нет). Работает только на Windows 2000/XP.

Обрати внимание на тип возвращаемого значения - HWND, а не HANDLE. Это не опечатка и не отдельный, "консольный" тип дескриптора - это тот же самый тип дескриптора ОКНА, что используется во ВСЕЙ остальной Windows, включая обычные графические приложения с кнопками и меню (категория User Interface Win32 API, о которой глава 1 сказала, что эта книга её не касается). Получается, что окно консоли - это полноценное, самое обычное окно Windows, просто изнутри показывающее не кнопки, а буфер экрана консоли. А раз это обычное окно - с ним можно работать самыми обычными функциями рисования (GDI, категория Graphics Device Interface), которые к консольным функциям вообще не относятся.

Пример - получение дескриптора окна и рисование на нём линии через GDI

Листинг 11.1 получает дескриптор окна консоли, а затем рисует на нём линию обычными функциями GDI - ровно демонстрация того, что окно консоли ничем не хуже обычного окна для рисования:

```c
#include <windows.h>
#include <stdio.h>

extern "C" WINBASEAPI HWND WINAPI GetConsoleWindow();

int main()
{
    HWND    hWindow = NULL;      // дескриптор окна
    HDC     hDeviceContext;      // контекст устройства
    HPEN    hPen;                // дескриптор пера
    HGDIOBJ hObject;             // дескриптор GDI объекта

    // получаем дескриптор окна
    hWindow = GetConsoleWindow();

    if (hWindow == NULL)
    {
        printf("Get console window failed.\n");
        return 1;
    }
    else
        printf("Get console window is done.\n");

    // получаем контекст устройства
    hDeviceContext = GetDC(hWindow);
    // создаем перо
    hPen = CreatePen(PS_SOLID, 10, RGB(0, 255, 0));
    // устанавливаем перо
    hObject = SelectObject(hDeviceContext, hPen);

    // рисуем линию
    MoveToEx(hDeviceContext, 100, 100, NULL);
    LineTo(hDeviceContext, 500, 100);

    // восстанавливаем старый объект
    SelectObject(hDeviceContext, hObject);

    // освобождаем объекты
    DeleteObject(hPen);
    ReleaseDC(hWindow, hDeviceContext);

    return 0;
}
```

Не скомпилировано по-настоящему (нет Windows/MSVC в этом окружении) - проверено по документации и логике API. Механизм по шагам: GetConsoleWindow даёт HWND окна консоли; GetDC(hWindow) получает "контекст устройства" - разрешение рисовать на этом конкретном окне; CreatePen создаёт зелёное перо толщиной 10 пикселей; SelectObject "вставляет" это перо в контекст устройства (и возвращает старый объект, который нужно будет вернуть обратно); MoveToEx/LineTo рисуют саму линию от точки (100,100) до точки (500,100); в конце - обязательная уборка за собой, ровно как с любым объектом ядра: вернуть исходный объект в контекст (SelectObject со старым hObject), удалить своё перо (DeleteObject), освободить контекст устройства (ReleaseDC). Ни одна из этих GDI-функций не является "консольной" - это ровно те же вызовы, которыми рисует любое обычное Windows-приложение с окнами.

11.2 Получение и изменение заголовка консоли

Для чтения заголовка окна консоли - функция GetConsoleTitle:

```
DWORD GetConsoleTitle(
    LPTSTR lpConsoleTitle,  // адрес буфера для заголовка
    DWORD  nSize            // размер буфера для заголовка в символах
);
```

При успехе возвращает длину строки с заголовком в символах, при неудаче - 0.

Для установки заголовка - функция SetConsoleTitle:

```
BOOL SetConsoleTitle(
    LPCTSTR lpConsoleTitle  // указатель на строку с заголовком
);
```

При успехе возвращает ненулевое значение, при неудаче - FALSE.

Пример - чтение и изменение заголовка консоли

Листинг 11.2 сначала читает текущий заголовок окна консоли, показывает его пользователю, затем спрашивает новый заголовок и устанавливает его:

```c
#include <windows.h>
#include <iostream.h>

int main()
{
    char  ConsoleTitleBuffer[80];  // указатель на буфер с заголовком
    DWORD dwBufferSize = 80;       // размер буфера для заголовка
    DWORD dwTitleSize;             // длина заголовка

    // читаем заголовок консоли
    dwTitleSize = GetConsoleTitle(ConsoleTitleBuffer, dwBufferSize);

    // выводим на консоль результат
    cout << "Title length = " << dwTitleSize << endl;
    cout << "The window title = " << ConsoleTitleBuffer << endl;

    cout << "Input new title: ";
    cin.getline(ConsoleTitleBuffer, 80);
    // устанавливаем новый заголовок консоли
    if (!SetConsoleTitle(ConsoleTitleBuffer))
        cout << "Set console title failed." << endl;

    cout << "The title was changed." << endl;
    cout << "Press any key to exit.";
    cin.get();

    return 0;
}
```

Не скомпилировано по-настоящему - проверено по документации и логике API.

11.3 Определение максимального размера окна

Максимальный размер окна консоли можно определить функцией GetLargestConsoleWindowSize:

```
COORD GetLargestConsoleWindowSize(
    HANDLE hConsoleOutput  // дескриптор буфера экрана
);
```

При успехе возвращает структуру COORD, где поле X - максимальное количество столбцов, а поле Y - максимальное количество строк окна консоли в символах. X и Y зависят от текущего размера шрифта и величины экрана - это не фиксированное число, а вычисляемое исходя из того, сколько символов физически влезет на экран этим шрифтом. При неудаче функция возвращает в полях структуры COORD нули.

Пример - определение максимальных размеров окна

Листинг 11.3 получает стандартный дескриптор вывода, а затем вызывает GetLargestConsoleWindowSize и печатает результат:

```c
#include <windows.h>
#include <iostream.h>

int main()
{
    HANDLE hConsoleOutput;  // дескриптор буфера экрана
    COORD  coord;           // координаты окна консоли

    // получаем дескриптор окна консоли
    hConsoleOutput = GetStdHandle(STD_OUTPUT_HANDLE);
    if (hConsoleOutput == INVALID_HANDLE_VALUE)
    {
        cout << "Get standard handle failed." << endl;
        return GetLastError();
    }
    // получаем максимальные размеры окна консоли
    coord = GetLargestConsoleWindowSize(hConsoleOutput);
    if (coord.X == 0 && coord.Y == 0)
    {
        cout << "Get largest console window size failed." << endl;
        return GetLastError();
    }

    cout << "Coordinate X = " << coord.X << endl;
    cout << "Coordinate Y = " << coord.Y << endl;

    cout << "Press any key to exit.";
    cin.get();

    return 0;
}
```

Не скомпилировано по-настоящему - проверено по документации и логике API. Обрати внимание на проверку ошибки: раз при неудаче функция кладёт в оба поля 0, а координата (0,0) сама по себе не может быть настоящим максимальным размером окна, проверка "оба поля равны нулю" однозначно отличает реальную ошибку от правдоподобного результата.

11.4 Установка координат окна

Установить окно консоли относительно буфера экрана можно функцией SetConsoleWindowInfo:

```
BOOL SetConsoleWindowInfo(
    HANDLE            hConsoleOutput,   // дескриптор буфера экрана
    BOOL              bAbsolute,        // тип координат
    CONST SMALL_RECT *lpConsoleWindow   // углы окна
);
```

hConsoleOutput должен быть открыт в режиме GENERIC_WRITE (подробно про открытие буфера экрана - глава 12). Параметр bAbsolute задаёт, как понимать координаты в lpConsoleWindow: FALSE - поля структуры SMALL_RECT задают СДВИГ левого верхнего и правого нижнего углов окна относительно ТЕКУЩЕГО положения окна консоли; TRUE - поля задают АБСОЛЮТНОЕ положение левого верхнего и правого нижнего углов окна относительно буфера экрана.

Для задания углов используется структура:

```c
typedef struct _SMALL_RECT {
    SHORT Left;    // x - координата левого верхнего угла окна консоли
    SHORT Top;     // y - координата левого верхнего угла окна консоли
    SHORT Right;   // x - координата правого нижнего угла окна консоли
    SHORT Bottom;  // y - координата правого нижнего угла окна консоли
} SMALL_RECT;
```

Координаты в SMALL_RECT определяют ЯЧЕЙКИ буфера экрана (то есть считаются не в пикселях, а в символах/строках) - это важно держать в голове, потому что окно консоли всегда меньше или равно буферу экрана, а не наоборот.

При успехе SetConsoleWindowInfo возвращает ненулевое значение, при неудаче - FALSE. Неудачное завершение может быть вызвано неправильным заданием координат окна: например координаты окна консоли превышают размер буфера экрана, либо не выполняется условие Left > 0, либо не выполняется условие Left < Right, и так далее. Отдельно отмечено, что в Windows 98 эта функция используется для прокрутки буфера экрана в окне консоли (то есть там это не столько "изменение размера", сколько единственный способ прокрутки).

Пример - установка окна в абсолютных координатах

Листинг 11.4 запрашивает у пользователя абсолютные координаты левого верхнего и правого нижнего углов окна и устанавливает их (bAbsolute = TRUE):

```c
#include <windows.h>
#include <iostream.h>

int main()
{
    HANDLE     hStdOut;  // дескриптор стандартного вывода
    SMALL_RECT sr;       // прямоугольник окна

    // читаем дескриптор стандартного вывода
    hStdOut = GetStdHandle(STD_OUTPUT_HANDLE);

    cout << "Set new window rectangle in characters." << endl << endl;

    // устанавливаем прямоугольник окна в символах
    cout << "Input left coordinate (0-79): ";
    cin >> sr.Left;
    cout << "Input top coordinate (0-24): ";
    cin >> sr.Top;
    cout << "Input right coordinate (0-79): ";
    cin >> sr.Right;
    cout << "Input bottom coordinate (0-24): ";
    cin >> sr.Bottom;
    // устанавливаем новое окно
    if (!SetConsoleWindowInfo(hStdOut, TRUE, &sr))
        cout << "Set console window info failed." << endl;

    cin.get();
    cout << endl << "Press any key to exit.";
    cin.get();

    return 0;
}
```

Не скомпилировано по-настоящему - проверено по документации и логике API.

Пример - установка окна в относительных координатах

Листинг 11.5 делает то же самое, но со сдвигом (bAbsolute = FALSE) - подсказки диапазона ввода в этом случае вычисляются относительно уже существующих координат, а не абсолютной сетки буфера:

```c
#include <windows.h>
#include <iostream.h>

int main()
{
    HANDLE     hStdOut;  // дескриптор стандартного вывода
    SMALL_RECT sr;       // прямоугольник окна

    // читаем дескриптор стандартного вывода
    hStdOut = GetStdHandle(STD_OUTPUT_HANDLE);

    cout << "Set new window rectangle in characters." << endl << endl;

    // устанавливаем прямоугольник окна в символах
    cout << "Input left coordinate (0-79): ";
    cin >> sr.Left;
    cout << "Input top coordinate (0-24): ";
    cin >> sr.Top;
    cout << "Input right coordinate (" << (sr.Left - 79) << ','
         << sr.Left << "): ";
    cin >> sr.Right;
    cout << "Input bottom coordinate (" << (sr.Top - 24) << ','
         << sr.Top << "): ";
    cin >> sr.Bottom;
    // устанавливаем новое окно в относительных координатах
    if (!SetConsoleWindowInfo(hStdOut, FALSE, &sr))
        cout << "Set console window info failed." << endl;

    cin.get();
    cout << endl << "Press key to exit.";
    cin.get();

    return 0;
}
```

Не скомпилировано по-настоящему - проверено по документации и логике API. Числовые пределы координат в этом листинге верны для Windows 2000 - в Windows 98 координаты правого нижнего угла при относительном сдвиге могут принимать только отрицательные значения (особенность именно этой версии системы, не общее правило).

Частые путаницы и ошибки

Путают дескриптор окна консоли (HWND от GetConsoleWindow) с дескриптором буфера экрана (HANDLE от GetStdHandle/CreateConsoleScreenBuffer, глава 12). Это два РАЗНЫХ дескриптора двух разных объектов - окно (то, что видно на экране, обычный Windows HWND, работает с GDI) и буфер экрана (то, куда пишутся символы, консольный HANDLE, работает с консольными функциями). Первый нельзя передать туда, где ждут второй, и наоборот.

Путают, что именно определяют координаты SMALL_RECT - это ячейки буфера экрана (строки/столбцы), а не пиксели экрана монитора. Отсюда и диапазоны в примерах "0-79", "0-24" - это число столбцов/строк, а не разрешение окна в пикселях.

Забывают, что окно консоли не может быть больше буфера экрана, на котором оно "показывается" - если задать координаты окна, выходящие за пределы текущего буфера, SetConsoleWindowInfo вернёт ошибку. Сначала увеличивают буфер (SetConsoleScreenBufferSize, глава 12), потом окно.

Путают режимы bAbsolute у SetConsoleWindowInfo. TRUE - координаты SMALL_RECT это абсолютное положение углов окна относительно буфера экрана. FALSE - это сдвиг относительно уже текущего положения окна, а не абсолютные координаты - перепутать легко, если не глядя скопировать пример.
