Лабораторная работа №5 - Код Хаффмана (вариант 5)

Вариант работы

Порядковый номер по списку группы - 10. В лабораторной 5 вариантов, номер варианта вычисляется по формуле (N-1) mod 5 + 1, где N - номер по списку: (10-1) mod 5 + 1 = 9 mod 5 + 1 = 4 + 1 = 5. Выполняется вариант 5.

Задание

1. Определить пропускную способность двоичного канала связи для передачи оптимального кода, построенного из алфавита L, G, N, P, D, B, T, X, если вероятности появления букв равны соответственно 0.2; 0.3; 0.01; 0.09; 0.3; 0.03; 0.04; 0.03, а время передачи одной буквы равно 0.1 с.
2. Построить оптимальный неравномерный код (ОНК) методом Хаффмана, если символы источника сообщений появляются с вероятностями A1 = A2 = A3 = A4 = 0.13; A5 = A6 = A7 = 0.16. Сравнить, насколько полученные коды близки к оптимальным.

Теоретическая часть

Код Хаффмана - неравномерный префиксный код: чем вероятнее сообщение, тем короче его кодовая комбинация. Префиксный означает, что ни одна кодовая комбинация не является началом другой, поэтому поток нулей и единиц однозначно разбивается на сообщения без разделителей. Из всех префиксных кодов, в которых каждому сообщению соответствует одна комбинация, код Хаффмана имеет наименьшую среднюю длину, то есть он оптимален. Код Шеннона-Фано (лабораторная 4) строится сверху вниз, делением таблицы на две части с близкими суммами вероятностей, и не всегда оптимален; код Хаффмана строится снизу вверх, склеиванием самых редких сообщений.

Почему склеиваются именно два самых редких сообщения. В оптимальном коде два самых редких сообщения получают самые длинные комбинации, причём одной длины, и отличаются только последним разрядом. Поэтому их можно заменить одним вспомогательным сообщением с суммарной вероятностью: получается такая же задача, но с одним сообщением меньше. При обратном ходе вспомогательное сообщение снова разделяется на два приписыванием разряда 0 или 1.

Построение (n - число сообщений):
1. Сообщения записываются в столбец в порядке убывания вероятностей.
2. Два последних сообщения объединяются в одно вспомогательное, его вероятность равна сумме их вероятностей.
3. Вероятности необъединённых сообщений и полученная сумма снова записываются в порядке убывания в следующий, вспомогательный, столбец; два последних сообщения нового столбца объединяются, и так далее.
4. Процесс продолжается, пока не останется одно сообщение с вероятностью 1. Объединений получается n - 1, поэтому и вспомогательных столбцов n - 1.
5. Кодовые комбинации получаются обратным ходом по таблице, от последнего столбца к первому: из двух объединённых сообщений верхнему приписывается 0, нижнему 1. У каждого сообщения цифры дописываются справа, по одной на каждое объединение, в котором оно участвовало, начиная с последнего.

Пример построения столбцов для шести сообщений с вероятностями 0.4; 0.2; 0.2; 0.1; 0.05; 0.05: исходный столбец 0.4 0.2 0.2 0.1 0.05 0.05; столбец 1: 0.4 0.2 0.2 0.1 0.1; столбец 2: 0.4 0.2 0.2 0.2; столбец 3: 0.4 0.4 0.2; столбец 4: 0.6 0.4; столбец 5: 1.

Если сумма по значению совпала с вероятностью другого сообщения, в работе она записывается выше равных (так длины комбинаций получаются более ровными); равные вероятности исходного алфавита идут в порядке исходной записи. Другой порядок равных вероятностей даёт другие комбинации, но ту же среднюю длину: все такие коды оптимальны.

Характеристики кода (p_i - вероятность i-го сообщения, l_i - длина его комбинации в двоичных символах, n - число сообщений):
- средняя длина L = sum(p_i * l_i), двоичных символов на сообщение;
- энтропия H = -sum(p_i * log2(p_i)), бит на сообщение; это нижняя граница средней длины любого кода: L >= H;
- избыточность L - H; эффективность H / L;
- для сравнения - равномерный код: ceil(log2(n)) двоичных символов на сообщение (ceil - округление вверх);
- пропускная способность двоичного канала без помех, необходимая для передачи кода. Время передачи одной буквы t - это интервал, с которым источник выдаёт буквы, то есть источник выдаёт 1 / t букв в секунду. Каждая буква в среднем занимает L двоичных символов, значит канал должен пропускать L / t двоичных символов в секунду. Один двоичный символ переносит не более 1 бита, поэтому C = L / t, бит/с. Меньше, чем H / t (производительность источника, бит/с), не получится ни при каком кодировании: C >= H / t.

Проверка результата

Программа без комментариев - файл "MG TI Turginbayeva A - Lab5 (Variant 5).java". Ниже та же программа с пояснениями, разбитая на семь блоков.

Идея. Вероятности хранятся целыми числами в сотых долях, поэтому суммы и сравнения вероятностей точные. Программа повторяет ручной расчёт: строит столбцы объединением двух последних сообщений, читает кодовые комбинации с дерева объединений, считает L, H, избыточность, эффективность и пропускную способность. Результат проверяется четырьмя способами: префиксность, неравенство Крафта, кодирование и декодирование туда-обратно, сравнение L с минимумом, найденным перебором всех допустимых наборов длин. Саму программу проверяет пример из методички (таблица 2): столбцы должны совпасть.

Схема связей. main три раза вызывает solve (задание 1, задание 2, пример методички). solve вызывает huffman (строит столбцы и дерево) и codes (читает с дерева комбинации), считает L и H и запускает проверки: prefixFree, roundTrip, minSum и total. Методы p, show и weights только форматируют вывод и вызываются из huffman и solve.

Блок 1. Данные и вывод

```java
import java.util.*;
import java.util.stream.*;

class Lab5Huffman {

    // сообщение: имя, вероятность в сотых долях (0.13 хранится как 13), два сообщения-слагаемых
    record Node(String name, int w, Node up, Node down) { }

    // результат построения: корень дерева, строки для печати, веса столбцов для сверки
    record Table(Node root, List<String> lines, String weights) { }

    // 13 -> "0.13"
    static String p(int w) {
        return String.format("%.2f", w / 100.0);
    }

    // столбец одной строкой: "имя вероятность | имя вероятность | ..."
    static String show(List<Node> col) {
        return col.stream().map(n -> n.name() + " " + p(n.w())).collect(Collectors.joining(" | "));
    }

    // только веса столбца: "40 20 20 10 10"
    static String weights(List<Node> col) {
        return col.stream().map(n -> String.valueOf(n.w())).collect(Collectors.joining(" "));
    }
```

Сообщение хранится в записи Node: name - имя (буква или S1, S2, ... у вспомогательных), w - вероятность в сотых долях (0.13 хранится как 13), up и down - верхнее и нижнее из двух объединённых сообщений (у обычного сообщения оба равны null). Вероятности целые, чтобы суммы и сравнения были точными, без ошибок округления дробей. Table - результат построения: корень дерева, строки для печати столбцов и веса столбцов для сверки с методичкой. Метод p переводит целую вероятность обратно в вид 0.13: формат %.2f даёт два знака после точки, делим на 100.0 (с точкой), чтобы деление было дробным, а не целочисленным. Методы show и weights печатают столбец целиком и только его веса.

Блок 2. Таблица столбцов (метод huffman)

```java
    // таблица столбцов; mergedHigh = true: сумму записывать выше равных вероятностей
    static Table huffman(List<Node> msgs, boolean mergedHigh) {
        List<Node> col = new ArrayList<>(msgs);
        // по убыванию вероятности, равные остаются в исходном порядке
        col.sort((a, b) -> b.w() - a.w());
        List<String> lines = new ArrayList<>(List.of("исходный столбец: " + show(col)));
        StringBuilder ws = new StringBuilder(weights(col));
        for (int step = 1; col.size() > 1; step++) {
            // два последних сообщения столбца
            Node down = col.remove(col.size() - 1);
            Node up = col.remove(col.size() - 1);
            // вспомогательное сообщение с суммарной вероятностью
            Node sum = new Node("S" + step, up.w() + down.w(), up, down);
            // место суммы в убывающем порядке
            int pos = 0;
            while (pos < col.size() && (col.get(pos).w() > sum.w() || (!mergedHigh && col.get(pos).w() == sum.w()))) pos++;
            col.add(pos, sum);
            lines.add("шаг " + step + ": " + sum.name() + " = " + up.name() + " + " + down.name() + " = " + p(sum.w()) + "; столбец: " + show(col));
            ws.append(" / ").append(weights(col));
        }
        // остался один узел - корень дерева
        return new Table(col.get(0), lines, ws.toString());
    }
```

col - текущий столбец. Сортировка с компаратором b.w() - a.w() даёт убывание вероятности (положительный результат ставит a после b); сортировка устойчивая, поэтому равные вероятности остаются в порядке исходной записи. В цикле два последних сообщения достаются вызовом remove(col.size() - 1): индекс размера минус 1 - это последний элемент; сначала берётся нижнее сообщение (down), потом верхнее (up). Их сумма становится новым сообщением sum с именем S и номером шага. Место суммы находит цикл с переменной pos: пропускаются все сообщения с большей вероятностью, а при mergedHigh = true остановка происходит на первой равной - сумма встаёт выше равных (при mergedHigh = false сумма встаёт ниже равных; это нужно для сравнения двух порядков). Цикл идёт, пока в столбце больше одного сообщения; оставшееся одно, с вероятностью 1.00, - корень дерева.

Блок 3. Кодовые комбинации и проверки кода

```java
    // обратный ход: к верхнему слагаемому дописываем 0, к нижнему 1
    static void codes(Node n, String prefix, Map<String, String> out) {
        if (n.up() == null) {
            out.put(n.name(), prefix);
        } else {
            codes(n.up(), prefix + "0", out);
            codes(n.down(), prefix + "1", out);
        }
    }

    // ни одна комбинация не начинается с другой
    static boolean prefixFree(Collection<String> codes) {
        List<String> c = new ArrayList<>(codes);
        for (int i = 0; i < c.size(); i++)
            for (int j = 0; j < c.size(); j++)
                if (i != j && c.get(j).startsWith(c.get(i))) return false;
        return true;
    }

    // кодируем список сообщений и декодируем обратно
    static boolean roundTrip(List<String> names, Map<String, String> code) {
        // склеиваем комбинации в одну строку из 0 и 1
        StringBuilder bits = new StringBuilder();
        names.forEach(s -> bits.append(code.get(s)));
        // обратная таблица: комбинация -> сообщение
        Map<String, String> back = new HashMap<>();
        code.forEach((s, c) -> back.put(c, s));
        List<String> out = new ArrayList<>();
        String cur = "";
        // читаем по одному символу; совпала с комбинацией - сообщение найдено
        for (char ch : bits.toString().toCharArray()) {
            cur += ch;
            if (back.containsKey(cur)) {
                out.add(back.get(cur));
                cur = "";
            }
        }
        return out.equals(names) && cur.isEmpty();
    }
```

Метод codes выполняет обратный ход по таблице: от корня к каждому сообщению дописывается 0 при переходе к верхнему слагаемому и 1 при переходе к нижнему; у обычного сообщения (up == null) накопленная строка записывается как его комбинация. Метод prefixFree сравнивает каждую пару комбинаций (i != j) через startsWith: если одна начинается с другой, код не префиксный. Метод roundTrip склеивает комбинации сообщений в строку из нулей и единиц, строит обратную таблицу "комбинация - сообщение" и декодирует: символы по одному добавляются в cur, как только cur совпал с какой-либо комбинацией, сообщение найдено и cur очищается. У префиксного кода совпадение единственное. Проверка проходит, если получен исходный список и в cur ничего не осталось.

Блок 4. Проверка оптимальности перебором

```java
    // минимум суммы w_i * l_i по всем наборам длин, для которых sum 2^-l <= 1
    static int minSum(int[] w, int i, int used, int maxLen) {
        if (i == w.length) return 0;
        int best = Integer.MAX_VALUE;
        for (int len = 1; len <= maxLen; len++) {
            // 2^-len в долях 2^-maxLen; не помещается - набор невозможен
            int u = used + (1 << (maxLen - len));
            if (u > 1 << maxLen) continue;
            int rest = minSum(w, i + 1, u, maxLen);
            if (rest != Integer.MAX_VALUE) best = Math.min(best, w[i] * len + rest);
        }
        return best;
    }

    // сумма w_i * l_i для построенного кода (в сотых долях символа)
    static int total(List<Node> sorted, Map<String, String> code) {
        return sorted.stream().mapToInt(m -> m.w() * code.get(m.name()).length()).sum();
    }
```

Префиксный код с длинами l_1, ..., l_n существует тогда и только тогда, когда sum 2^(-l_i) <= 1 (неравенство Крафта). Метод minSum перебирает длины всех сообщений от 1 до maxLen. Величина 2^(-len) считается целым числом в долях 2^(-maxLen): выражение 1 << (maxLen - len) - это 2 в степени maxLen - len. В used накапливается сумма таких долей, и набор, для которого она больше 1 (u > 1 << maxLen), отбрасывается. Метод возвращает минимум суммы w_i * l_i. При вызове из solve в параметр maxLen передаётся n - 1: длиннее комбинации быть не может, потому что в двоичном дереве с n листьями глубина листа не больше n - 1. Метод total считает ту же сумму для построенного кода; если минимум и total совпали, код Хаффмана оптимален.

Блок 5. Метод solve, часть 1 из 2: построение и характеристики

```java
    // t - время передачи одной буквы в секундах (0 - пропускную способность не считать)
    static String solve(String title, String[] names, int[] w, double t) {
        System.out.println("=== " + title + " ===");
        List<Node> msgs = new ArrayList<>();
        for (int i = 0; i < w.length; i++) msgs.add(new Node(names[i], w[i], null, null));
        List<Node> sorted = new ArrayList<>(msgs);
        sorted.sort((a, b) -> b.w() - a.w());

        // таблица столбцов и кодовые комбинации
        Table table = huffman(msgs, true);
        table.lines().forEach(System.out::println);
        Map<String, String> code = new HashMap<>();
        codes(table.root(), "", code);
        for (Node m : sorted)
            System.out.printf("%-3s p = %s  код %-6s длина %d%n", m.name(), p(m.w()), code.get(m.name()), code.get(m.name()).length());

        // средняя длина, энтропия, равномерный код
        double L = total(sorted, code) / 100.0, H = 0;
        for (Node m : sorted) H -= m.w() / 100.0 * Math.log(m.w() / 100.0) / Math.log(2);
        int uniform = 32 - Integer.numberOfLeadingZeros(w.length - 1);
        System.out.printf("L = %.4f; H = %.4f; L - H = %.4f; H/L = %.2f%%%n", L, H, L - H, H / L * 100);
        System.out.printf("равномерный код: %d двоичных символа на сообщение, эффективность H/%d = %.2f%%%n", uniform, uniform, H / uniform * 100);
```

Параметры solve: names - имена сообщений, w - вероятности в сотых долях, t - время передачи одной буквы в секундах (0 - пропускную способность не считать). Сначала сообщения превращаются в узлы и сортируются (sorted - порядок печати). Вызов huffman(msgs, true) строит таблицу, codes получает комбинации. В printf формат %-3s - строка шириной 3 символа с выравниванием влево, %s - строка, %d - целое число, %n - перевод строки. Средняя длина L равна total / 100.0. Энтропия H: в Java нет логарифма по основанию 2, поэтому log2(x) вычисляется как Math.log(x) / Math.log(2). Длина равномерного кода - число двоичных разрядов числа n - 1, то есть ceil(log2(n)): выражение 32 - Integer.numberOfLeadingZeros(n - 1) (numberOfLeadingZeros возвращает число нулей слева в 32-разрядной записи числа). Формат %.4f - четыре знака после точки, %% - знак процента.

Ответы на контрольные вопросы

1) Что такое код Хаффмана?
Код Хаффмана - неравномерный префиксный код, оптимальный для источника с известными вероятностями сообщений (предложен Д. Хаффманом в 1952 г.). Чем вероятнее сообщение, тем короче его кодовая комбинация; никакая комбинация не является началом другой, поэтому поток нулей и единиц декодируется однозначно без разделителей. Из всех префиксных кодов, в которых каждому сообщению соответствует отдельная комбинация, у кода Хаффмана наименьшая средняя длина L. Она удовлетворяет условию H <= L < H + 1 (H - энтропия источника) и равна H, когда все вероятности являются целыми отрицательными степенями двойки. В отличие от кода Шеннона-Фано, который строится сверху вниз (делением таблицы на две части с близкими суммами вероятностей) и не всегда оптимален, код Хаффмана строится снизу вверх (объединением самых редких сообщений) и оптимален всегда. Пример - задание 2: L = 2.84 при H = 2.7996, эффективность 98.58%, и меньшей средней длины не даёт никакой префиксный код.

2) Как строятся кодовые комбинации в коде Хаффмана?
1. Сообщения записываются в столбец в порядке убывания вероятностей.
2. Два последних сообщения объединяются в одно вспомогательное с суммарной вероятностью; вероятности снова записываются в порядке убывания в следующий столбец, и два последних опять объединяются. Так продолжается, пока не останется одно сообщение с вероятностью 1.
3. Обратным ходом по таблице, от последнего столбца к первому, из двух объединённых сообщений верхнему приписывается 0, нижнему 1. У каждого сообщения цифры дописываются справа, по одной на каждое объединение, в котором оно участвовало; получившаяся последовательность и есть его кодовая комбинация.
Пример - задание 2: S6 = S5 + S4 даёт S5 - 0 и S4 - 1; S4 = S1 + A5 даёт S1 - 10 и A5 - 11; S1 = A3 + A4 даёт A3 - 100 и A4 - 101. Остальные комбинации получаются так же: A6 - 000, A7 - 001, A1 - 010, A2 - 011.

3) Как строится таблица вероятностей?
Таблица (как таблица 2 методички) состоит из столбца номеров сообщений, столбца их вероятностей в порядке убывания и вспомогательных столбцов 1, 2, ... Каждый следующий столбец получается из предыдущего так: два последних (наименьших) значения заменяются их суммой, остальные переписываются без изменений, и всё снова располагается в порядке убывания (сумма встаёт на своё место по величине); фигурная скобка и стрелка в таблице показывают, какие два значения объединены. Столбец при этом становится короче на одну строку, поэтому для n сообщений вспомогательных столбцов n - 1, а последний содержит единственное число 1. Пример - задание 2: исходный столбец из 7 вероятностей и 6 вспомогательных столбцов длиной 6, 5, 4, 3, 2 и 1 элемент.
