Задание

1. Построить оптимальный код сообщений, если вероятности появления букв первичного алфавита, состоящего из 8 знаков, являются целыми отрицательными степенями двойки, а сумма вероятностей равна 1.
2. Построить оптимальный неравномерный код (ОНК) методом Шеннона-Фано, если символы источника сообщений появляются с вероятностями A1 = A2 = A3 = A4 = 0.19; A5 = A6 = A7 = 0.08. Сравнить, насколько полученные коды близки к оптимальным.

Теоретическая часть

Код Шеннона-Фано - неравномерный префиксный код: чем вероятнее сообщение, тем короче его кодовая комбинация. Основной принцип: каждый разряд кодовой комбинации должен нести как можно больше информации, то есть независимо от значений предыдущих разрядов принимать значения 0 и 1 с (по возможности) равной вероятностью.

Построение кодовых комбинаций:
1. Сообщения записываются в таблицу в порядке убывания вероятностей.
2. Таблица делится на две части так, чтобы суммы вероятностей в частях были как можно ближе. Если возможны два разбиения с одинаково близкими суммами, сообщение, которым они различаются, относится к верхней подгруппе.
3. В верхней подгруппе старшим разрядом кодовой комбинации записывается 0, в нижней - 1.
4. Деление подгрупп по п. 2 повторяется, пока в подгруппе не останется одно сообщение.

Характеристики кода (p_i - вероятность i-го сообщения, l_i - длина его кодовой комбинации в двоичных символах):
- средняя длина кодовой комбинации L = sum(p_i * l_i), двоичных символов на сообщение;
- энтропия источника H = -sum(p_i * log2(p_i)), бит на сообщение; это нижняя граница средней длины любого кода: L >= H;
- избыточность кода L - H; эффективность кода H / L. Чем ближе L к H, тем ближе код к оптимальному.
Оптимальным считается код с наименьшей возможной средней длиной среди префиксных кодов для данного распределения вероятностей.

Задание 1

Условие: 8 букв, вероятности - целые отрицательные степени двойки, сумма равна 1. Берём распределение p_i = 2^(-i) для первых семи букв: 1/2, 1/4, 1/8, 1/16, 1/32, 1/64, 1/128. Их сумма равна 1 - 1/128, поэтому чтобы общая сумма стала равна 1, вероятность восьмой буквы должна быть 1/128 = 2^(-7) (это тоже целая отрицательная степень двойки).

Вероятности (уже упорядочены по убыванию):
a1 = 1/2 = 0.5
a2 = 1/4 = 0.25
a3 = 1/8 = 0.125
a4 = 1/16 = 0.0625
a5 = 1/32 = 0.03125
a6 = 1/64 = 0.015625
a7 = 1/128 = 0.0078125
a8 = 1/128 = 0.0078125
Проверка: 0.5 + 0.25 + 0.125 + 0.0625 + 0.03125 + 0.015625 + 0.0078125 + 0.0078125 = 1.

Построение кода:
1) {a1} = 0.5 | {a2..a8} = 0.5 - суммы равны. Буква a1 получает 0 (код 0 окончательный), остальным приписывается 1.
2) {a2} = 0.25 | {a3..a8} = 0.25. a2 - код 10, остальным приписывается 11.
3) {a3} = 0.125 | {a4..a8} = 0.125. a3 - код 110, остальным 111.
4) {a4} = 0.0625 | {a5..a8} = 0.0625. a4 - код 1110, остальным 1111.
5) {a5} = 0.03125 | {a6..a8} = 0.03125. a5 - код 11110, остальным 11111.
6) {a6} = 0.015625 | {a7, a8} = 0.015625. a6 - код 111110, остальным 111111.
7) {a7} = 0.0078125 | {a8} = 0.0078125. a7 - код 1111110, a8 - код 1111111.

Кодовая таблица:
a1  0.5        0         (l = 1)
a2  0.25       10        (l = 2)
a3  0.125      110       (l = 3)
a4  0.0625     1110      (l = 4)
a5  0.03125    11110     (l = 5)
a6  0.015625   111110    (l = 6)
a7  0.0078125  1111110   (l = 7)
a8  0.0078125  1111111   (l = 7)

На каждом шаге суммы вероятностей в частях равны точно, поэтому каждый разряд принимает значения 0 и 1 с вероятностью 1/2 и несёт ровно 1 бит информации.

Средняя длина: L = 0.5 * 1 + 0.25 * 2 + 0.125 * 3 + 0.0625 * 4 + 0.03125 * 5 + 0.015625 * 6 + 0.0078125 * 7 + 0.0078125 * 7 = 0.5 + 0.5 + 0.375 + 0.25 + 0.15625 + 0.09375 + 0.0546875 + 0.0546875 = 1.984375 двоичных символов на букву.

Энтропия: так как p_i = 2^(-l_i), то -log2(p_i) = l_i для каждой буквы, поэтому H = sum(p_i * l_i) = 1.984375 бит на букву. Значит L = H, избыточность равна 0, эффективность 100%: код оптимален и идеально согласован с источником. Для сравнения: равномерный код для 8 букв требует log2(8) = 3 двоичных символа на букву, то есть выигрыш составляет 3 - 1.984375 = 1.015625 символа на букву (около 33.85%).

Общий вывод: для любого набора вероятностей вида 2^(-k_i) с суммой 1 метод Шеннона-Фано на каждом шаге делит группу ровно пополам, длины кодовых комбинаций получаются l_i = k_i = -log2(p_i), и код не имеет избыточности.

Задание 2

Исходные данные: A1 = A2 = A3 = A4 = 0.19; A5 = A6 = A7 = 0.08. Проверка суммы: 4 * 0.19 + 3 * 0.08 = 0.76 + 0.24 = 1.00. Сообщения уже упорядочены по убыванию вероятностей.

Шаг 1. Первое разбиение (сумма 1.00, идеальная половина 0.50). Возможные разбиения:
- после A2: 0.38 | 0.62, разность 0.24;
- после A3: 0.57 | 0.43, разность 0.14;
- после A4: 0.76 | 0.24, разность 0.52.
Остальные разбиения дают ещё большую разность. Выбирается разбиение после A3: верхняя подгруппа {A1, A2, A3} (0.57) получает 0, нижняя {A4, A5, A6, A7} (0.43) получает 1.

Шаг 2. Верхняя подгруппа {A1, A2, A3}:
- {A1} | {A2, A3}: 0.19 | 0.38, разность 0.19;
- {A1, A2} | {A3}: 0.38 | 0.19, разность 0.19.
Суммы одинаково близки. По правилу сообщение, которым разбиения различаются (A2), относится к верхней подгруппе, то есть выбирается {A1, A2} | {A3}. A3 получает 01 (код окончательный). Подгруппа {A1, A2} делится на {A1} и {A2}: A1 - 000, A2 - 001.

Шаг 3. Нижняя подгруппа {A4, A5, A6, A7} (0.43):
- {A4} | {A5, A6, A7}: 0.19 | 0.24, разность 0.05;
- {A4, A5} | {A6, A7}: 0.27 | 0.16, разность 0.11;
- {A4, A5, A6} | {A7}: 0.35 | 0.08, разность 0.27.
Выбирается первое: A4 - 10 (код окончательный), подгруппа {A5, A6, A7} получает префикс 11.

Шаг 4. Подгруппа {A5, A6, A7} (0.24):
- {A5} | {A6, A7}: 0.08 | 0.16, разность 0.08;
- {A5, A6} | {A7}: 0.16 | 0.08, разность 0.08.
Снова равенство: сообщение A6 относится к верхней подгруппе, выбирается {A5, A6} | {A7}. A7 - 111 (окончательный), а {A5, A6} делится на A5 - 1100 и A6 - 1101.

Кодовая таблица:
A1  0.19  000   (l = 3)
A2  0.19  001   (l = 3)
A3  0.19  01    (l = 2)
A4  0.19  10    (l = 2)
A5  0.08  1100  (l = 4)
A6  0.08  1101  (l = 4)
A7  0.08  111   (l = 3)
Ни одна кодовая комбинация не является началом другой (префиксное свойство выполнено), поэтому сообщения декодируются однозначно.

Средняя длина: L = 0.19 * 3 + 0.19 * 3 + 0.19 * 2 + 0.19 * 2 + 0.08 * 4 + 0.08 * 4 + 0.08 * 3 = 0.57 + 0.57 + 0.38 + 0.38 + 0.32 + 0.32 + 0.24 = 2.78 двоичных символа на сообщение.

Энтропия (округление до 6 знаков в слагаемых, до 4 в результате):
-log2(0.19) = 2.395929, 0.19 * 2.395929 = 0.455226;
-log2(0.08) = 3.643856, 0.08 * 3.643856 = 0.291508;
H = 4 * 0.455226 + 3 * 0.291508 = 1.820904 + 0.874524 = 2.695428, то есть H = 2.6954 бит на сообщение.

Сравнение с оптимальным кодом:
- избыточность L - H = 2.78 - 2.6954 = 0.0846 двоичного символа на сообщение; эффективность H / L = 2.6954 / 2.78 = 0.9696, то есть 96.96%. Остаточная избыточность неизбежна: вероятности 0.19 и 0.08 не являются степенями двойки, поэтому энтропию точно достичь нельзя (в отличие от задания 1, где избыточность равна 0);
- равномерный код для 7 сообщений требует 3 двоичных символа (2^3 = 8 >= 7), полученный код короче на 3 - 2.78 = 0.22 символа на сообщение (около 7.33%);
- для проверки оптимальности построен код Хаффмана (оптимальный префиксный код): его средняя длина равна 2.78, то есть совпадает с длиной кода Шеннона-Фано. Значит полученный код оптимален: короче префиксного кода для этого распределения не существует.

Замечание о неоднозначности. При равных суммах на шагах 2 и 4 возможны два разбиения. Если спорное сообщение на этих шагах отнести не в верхнюю, а в нижнюю подгруппу, получается другой код: A1 - 00, A2 - 010, A3 - 011, A4 - 10, A5 - 110, A6 - 1110, A7 - 1111. Его средняя длина: 0.19 * (2+3+3+2) + 0.08 * (3+4+4) = 1.90 + 0.88 = 2.78 - такая же. Оба кода равноценны и оптимальны.

Для проверки написана программа на Python. Она строит код по описанному алгоритму (сортировка по убыванию, разбиение с наименьшей разностью сумм, при равных разностях - спорное сообщение в верхнюю подгруппу), вычисляет среднюю длину, энтропию и эффективность, проверяет неравенство Крафта, префиксное свойство и декодирование, а для сравнения строит код Хаффмана. Вероятности хранятся точными дробями, поэтому равенство сумм определяется без ошибок округления. Программа также проверена на примере из методички (таблица 1, вероятности 0.21; 0.15; 0.15; 0.14; 0.13; 0.08; 0.06; 0.06; 0.02).

```python
from fractions import Fraction
from math import log2
import heapq


def split_point(items, tie_to_upper=True):
    """items: [(символ, вероятность)], отсортированы по убыванию.
    Возвращает размер верхней подгруппы: суммы вероятностей частей максимально близки."""
    total = sum(p for _, p in items)
    best_k, best_diff, upper = None, None, Fraction(0)
    for k in range(1, len(items)):
        upper += items[k - 1][1]
        diff = abs(2 * upper - total)              # |верх - низ|
        if best_diff is None or diff < best_diff or (diff == best_diff and tie_to_upper):
            best_k, best_diff = k, diff
    return best_k


def shannon_fano(items, tie_to_upper=True, prefix="", codes=None, trace=None):
    if codes is None:
        codes = {}
    if len(items) == 1:
        codes[items[0][0]] = prefix
        return codes
    k = split_point(items, tie_to_upper)
    if trace is not None:
        up, low = items[:k], items[k:]
        trace.append((prefix, [s for s, _ in up], sum(p for _, p in up), [s for s, _ in low], sum(p for _, p in low)))
    shannon_fano(items[:k], tie_to_upper, prefix + "0", codes, trace)
    shannon_fano(items[k:], tie_to_upper, prefix + "1", codes, trace)
    return codes


def build(probs, tie_to_upper=True):
    items = sorted(probs, key=lambda x: -x[1])      # по убыванию вероятности
    trace = []
    return items, shannon_fano(items, tie_to_upper, trace=trace), trace


def huffman_length(items):
    heap = [(p, i, [s]) for i, (s, p) in enumerate(items)]
    heapq.heapify(heap)
    depth, counter = {s: 0 for s, _ in items}, len(items)
    while len(heap) > 1:
        p1, _, g1 = heapq.heappop(heap)
        p2, _, g2 = heapq.heappop(heap)
        for s in g1 + g2:
            depth[s] += 1
        heapq.heappush(heap, (p1 + p2, counter, g1 + g2))
        counter += 1
    return float(sum(p * depth[s] for s, p in items))


def report(title, probs, tie_to_upper=True, show_trace=True):
    items, codes, trace = build(probs, tie_to_upper)
    print(f"--- {title} ---")
    if show_trace:
        for prefix, up, sup, low, slow in trace:
            print(f"разбиение группы (префикс '{prefix}'): верх {up} = {float(sup):g} | низ {low} = {float(slow):g}")
    for s, p in items:
        print(f"{s:>3}  p = {float(p):<10g} код {codes[s]:<9} длина {len(codes[s])}")
    L = float(sum(p * len(codes[s]) for s, p in items))
    H = -sum(float(p) * log2(float(p)) for _, p in items)
    kraft = sum(Fraction(1, 2 ** len(c)) for c in codes.values())
    prefix_free = all(not b.startswith(a) for a in codes.values() for b in codes.values() if a is not b)
    msg = [s for s, _ in items] * 3
    bits = "".join(codes[s] for s in msg)
    rev, out, cur = {c: s for s, c in codes.items()}, [], ""
    for bit in bits:
        cur += bit
        if cur in rev:
            out.append(rev[cur]); cur = ""
    print(f"сумма вероятностей = {float(sum(p for _, p in items)):g}")
    print(f"средняя длина L = {L:.4f}; энтропия H = {H:.4f}; L - H = {L - H:.4f}; H/L = {H / L * 100:.2f}%")
    print(f"равномерный код: {len(bin(len(items) - 1)) - 2} бит/символ; код Хаффмана L = {huffman_length(items):.4f}")
    print(f"неравенство Крафта: сумма 2^-l = {kraft}; префиксность: {prefix_free}; декодирование туда-обратно: {out == msg}")
    print()
    return codes


F = Fraction
```

Ответы на контрольные вопросы

1) Что такое код Шеннона-Фано?
Код Шеннона-Фано - неравномерный префиксный код для эффективного кодирования сообщений источника с заданными вероятностями (назван по именам К. Шеннона и Р. Фано). Сообщениям с большей вероятностью соответствуют короткие кодовые комбинации, с меньшей - длинные, поэтому средняя длина кодовой комбинации получается близкой к энтропии источника и сообщение занимает меньше места, чем при равномерном коде. Префиксное свойство (никакая кодовая комбинация не является началом другой) позволяет однозначно декодировать поток без разделителей между комбинациями.

2) Как строятся кодовые комбинации?
1. Сообщения и их вероятности записываются в таблицу в порядке убывания вероятностей.
2. Таблица делится на две части так, чтобы суммы вероятностей в частях были как можно ближе. Если возможны два разбиения с одинаково близкими суммами, сообщение, которым они различаются, относится к верхней подгруппе.
3. В верхней подгруппе старшим разрядом кодовой комбинации записывается 0, в нижней - 1.
4. Деление подгрупп по п. 2 повторяется, пока в подгруппе не останется одно сообщение; накопленная последовательность нулей и единиц и есть его кодовая комбинация.
Пример - задание 2: разбиение {A1, A2, A3} | {A4, A5, A6, A7} (0.57 и 0.43) даёт первым разрядам 0 и 1, дальнейшие разбиения приводят к комбинациям 000, 001, 01, 10, 1100, 1101, 111.

3) Каков основной принцип кодирования Шеннона-Фано?
При выборе каждого разряда кодовой комбинации нужно стремиться к тому, чтобы он нёс как можно больше информации, то есть независимо от значений всех предыдущих разрядов принимал значения 0 и 1 с (по возможности) равной вероятностью. Разряд с равновероятными значениями несёт ровно 1 бит информации - максимум для двоичного разряда. Поэтому каждая группа сообщений делится на две части с почти равными суммами вероятностей. В результате длина кодовой комбинации тем больше, чем меньше вероятность сообщения (в идеале l_i равна -log2(p_i)): вероятные сообщения получают короткие комбинации, редкие - длинные.
